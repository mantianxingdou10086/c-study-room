<KeyPoint>
  转换说明是在告诉 printf「按什么方式解释这块内存」。解释方式和实际数据不匹配时，
  printf 不会知道，它只会照着你的话去读——于是输出一个毫无意义的数字。
</KeyPoint>

## 一张对照表（这一节的核心）

| 你要打印的东西 | 用哪个 | 例子 | 结果 |
|---|---|---|---|
| 整数 | `%d` | `printf("%d", 42)` | `42` |
| 浮点数 | `%f` | `printf("%f", 3.5)` | `3.500000` |
| 单个字符 | `%c` | `printf("%c", 'A')` | `A` |
| 字符串 | `%s` | `printf("%s", "hi")` | `hi` |
| 百分号本身 | `%%` | `printf("80%%")` | `80%` |

<Callout type="warn" title="用错不会报错——这才是最麻烦的地方">
  ```c
  double price = 9.9;
  printf("%d\n", price);   /* 编译可能只有警告，运行输出一个随机数 */
  ```
  `%d` 让 printf 按整数的方式去读那块内存，而浮点数的内存排布完全不同，
  读出来自然是个垃圾值。**程序不崩溃，只是安静地错**。
</Callout>

## 同一个值，两种解释

字符在 C 里其实就是小整数。ASCII 表里 `'A'` 是 65，`'B'` 是 66。所以：

```c
int n = 65;
printf("%d\n", n);   /* 65 —— 当数字看 */
printf("%c\n", n);   /* A  —— 当字符看 */
```

同一串比特，用 `%d` 解释得到数字，用 `%c` 解释得到字符。这也解释了为什么
`'a' - 'A'` 能算出 32 这种「字母间距」——它们本来就是数字。

<TryIt title="同一个值的两种样子">
{`#include <stdio.h>

int main(void)
{
    int n = 65;

    printf("当数字看：%d\\n", n);
    printf("当字符看：%c\\n", n);
    return 0;
}
`}
</TryIt>

## 数量必须对齐

占位符的个数要和后面参数的个数一致：

```c
printf("%d %d\n", 5);         /* ❌ 一个参数喂两个占位符 → 第二个打印随机值 */
printf("%d\n", 5, 6);         /* ⚠️ 多余的参数被忽略（有些编译器会警告） */
```

<Pitfall title="%f 默认打印 6 位小数">
  `printf("%f\n", 3.5)` 输出 `3.500000`，不是 `3.5`。
  要控制位数用 `%.2f` 这种写法（下一节细讲）。
  第一次见到这个输出时，很多人会以为「算错了」——其实只是默认格式。
</Pitfall>

<Pitfall title="double 在 scanf 里要用 %lf">
  printf 里 double 用 `%f` 就行，但 **scanf 里必须用 `%lf`**。
  这是 C 语言里一个著名的不一致，写错了读进来的值就是错的。
</Pitfall>
