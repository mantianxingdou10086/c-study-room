## 任务

> 读入三个整数成绩，输出一行：三个成绩各占 4 个字符宽（右对齐），
> 然后输出「平均」和平均分（保留 1 位小数）。

输入 `88 92 75`，期望输出：

```
  88  92  75 平均 85.0
```

注意开头那 2 个空格——它们是 `%4d` 补出来的，**也是输出的一部分**。

## 拆解

**第 1 步：读数据**

```c
int a, b, c;
scanf("%d %d %d", &a, &b, &c);
```

**第 2 步：算平均分（小心整数除法）**

```c
double avg = (a + b + c) / 3.0;    /* 3.0 不是 3！ */
```

用 `3` 的话，`255 / 3` 在整数世界里是 85（这里恰好整除，看不出问题），
但换成 `88 92 76` 就会丢掉小数——**这类 bug 只在部分输入下出现**，最容易被漏掉。

**第 3 步：按格式输出**

```c
printf("%4d%4d%4d 平均 %.1f\n", a, b, c, avg);
```

一个 printf 就能搞定：三个 `%4d` 各占 4 字符宽，中间没有额外空格（宽度里已经含了）。

<Callout type="warn" title="输出格式是需求，不是自由发挥">
  如果你写成 `printf("%d %d %d 平均 %.1f\n", ...)`，输出是 `88 92 75 平均 85.0`——
  看着差不多，但**开头少了两个空格**，判题会判错。
  在真实项目里也一样：接口输出格式变了，下游程序就崩了。
</Callout>

## 完整程序

```c
#include <stdio.h>

int main(void)
{
    int a, b, c;
    double avg;

    scanf("%d %d %d", &a, &b, &c);
    avg = (a + b + c) / 3.0;
    printf("%4d%4d%4d 平均 %.1f\n", a, b, c, avg);
    return 0;
}
```

## 动手：把这张表做成一列

上面的程序只输出一行。真实成绩单是**多行**的，每行格式相同——那就需要循环（第 6 章）。
现在先做到能稳定输出一行，把格式控制练熟。

<TryIt title="改改宽度和精度，观察输出变化" stdin="88 92 75">
{`#include <stdio.h>

int main(void)
{
    int a, b, c;

    scanf("%d %d %d", &a, &b, &c);

`}
</TryIt>

试着把 `%4d` 改成 `%6d`、把 `%.1f` 改成 `%.3f`，再试一次——直到你能**预判**输出长什么样。

<Pitfall title="在 printf 里手工数空格">
  ```c
  printf("  %d  %d  %d 平均 %.1f\n", ...);   /* ❌ 数据一变就错位 */
  ```
  空格数量是固定的，而数据位数会变。**宽度控制就是为了让你不必手工数空格**。
</Pitfall>

<Pitfall title="忘了 \n">
  少一个换行符，下一次输出会接在同一行末尾。单行程序看不出来，
  多行输出时会糊成一团——这也是为什么这个坑常常到第 6 章才暴露。
</Pitfall>
