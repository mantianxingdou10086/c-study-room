<KeyPoint>
  scanf 的算法很机械：**跳过开头的空白 → 按转换说明尽量多读 → 遇到不匹配就停**。
  停下时它会把不匹配的字符**留在原地**，这就是后面一切怪现象的根源。
</KeyPoint>

## 三步流程

读 `scanf("%d", &n)`，用户输入 `42abc`：

1. **跳过空白**：开头有空格、换行、Tab 就跳过
2. **尽量多读**：`%d` 认数字、正负号，读到 `a` 发现不是数字，停
3. **转换并存入**：把 `42` 转成整数存进 `n`

`abc` 还在输入缓冲区里，等下一次读取来碰它。

<Callout type="warn" title="scanf 不会报错，也不会告诉你它读到了多少">
  `42abc` 输入下，程序会安静地拿到 42，你以为一切正常——
  直到后面某次读取出问题。**永远不要假设用户输入是你期望的样子**，
  这在第 24 章「错误处理」里会正式处理。
</Callout>

## 空白字符的处理（最容易踩的地方）

| 转换说明 | 前面的空白会怎样 |
|---|---|
| `%d`、`%f` | **自动跳过**（所以 `3 4`、`3\n4` 都能读到两个数） |
| `%c` | **不跳过**！读到什么就是什么，包括空格和换行 |

这就是那个经典现象：先用 `%d` 读数字、再用 `%c` 读字符，`%c` 拿到的是**上一行的回车**。

修法有两种：

```c
scanf(" %c", &ch);     /* ✅ % 前面加一个空格：让 scanf 先跳过空白 */
```

```c
getchar();             /* 或者手动把那个换行读走 */
scanf("%c", &ch);
```

## 格式串里的空白和普通字符

- 格式串里的**空白**（空格、Tab、换行）表示「跳过任意多个空白字符」
- 格式串里的**普通字符**表示「必须原样匹配」，这几乎总是错：

```c
scanf("%d 个", &n);    /* ❌ 用户必须真的输入「个」才能继续 */
```

<Pitfall title="scanf 的返回值被忽略">
  `scanf` 会返回**成功读到的项数**。`scanf("%d", &n)` 成功返回 1，读到非数字返回 0。
  现在可以先知道有这回事，检查它的返回值是最基本的输入校验：
  ```c
  if (scanf("%d", &n) != 1) {
      printf("输入不是一个整数\n");
  }
  ```
</Pitfall>

<Pitfall title="一次读取用两个函数混着读">
  `scanf` 和 `getchar` 共用同一个输入缓冲区，混用时要特别小心谁把换行吃掉了。
  新手阶段建议**一次只用一种**：要么全 scanf，要么全 getchar。
</Pitfall>

## 这一节的结论

scanf 是「跳过空白 → 尽量读 → 不匹配就停」。`%c` 不跳空白、`%lf` 读 double、
格式串里别写普通字符——记住这三条，能避开大半输入问题。
