## 坑 1：scanf 忘了 `&`

```c
int n;
scanf("%d", n);     /* ❌ 少了 & */
```

**表现**：程序可能直接崩溃（scanf 把 n 的当前值当成内存地址去写），
也可能「看起来正常」但 n 一直是垃圾值。

**修法**：scanf 的每个变量前都要有 `&`。这是初学者第一大错误，没有之一。

## 坑 2：转换说明与类型不匹配

```c
double x = 1.5;
printf("%d\n", x);    /* ❌ 打印垃圾 */
int n;
scanf("%lf", &n);     /* ❌ 读进 int 却按 double 解析 */
```

**表现**：不报错，输出/读入的值毫无意义。

**修法**：对照第 1 节那张表。特别记住：**scanf 读 double 用 `%lf`**。

## 坑 3：`%c` 读到了上一行的回车

```c
int n;
char ch;
scanf("%d", &n);
scanf("%c", &ch);     /* ❌ ch 拿到的是 '\n' */
```

**表现**：程序看起来「跳过了」这次输入，ch 里是个看不见的字符。

**修法**：`scanf(" %c", &ch);`（`%` 前加空格），或者先 `getchar();` 吃掉换行。

## 坑 4：`scanf` 格式串里写了多余的字

```c
scanf("请输入：%d", &n);   /* ❌ 用户必须真的输入「请输入：」 */
```

**表现**：用户正常输入数字后程序卡住不动，因为它在等一个永远不会出现的匹配。

**修法**：提示语用 `printf` 单独打印，scanf 的格式串里只放转换说明和空白。

## 坑 5：输出格式和题目要求不一致

```c
/* 题目要求：输出保留 2 位小数 */
printf("%f\n", avg);     /* ❌ 输出 85.500000 */
printf("%d\n", avg);     /* ❌ 输出垃圾 */
printf("%.2f\n", avg);   /* ✅ 输出 85.50 */
```

**表现**：程序算对了，但判题说你错。多一个空格、少一个换行、多两位小数，都算错。

**修法**：把「输出格式」当成需求的一部分，而不是可以随意决定的细节。

<Callout type="tip" title="一个自检习惯">
  写完之后，**先在心里跑一遍最普通的输入**（比如题目给的例子），
  再跑一遍**边界输入**（0、负数、不能被整除的数）。
  上面五个坑里，有四个都能被这两种输入暴露出来。
</Callout>

<TryIt title="坑 2 现场：用 %d 打印 double" stdin="">
{`#include <stdio.h>

int main(void)
{
    double x = 1.5;

    printf("按 %%f 打印：%f\\n", x);
    printf("按 %%d 打印：%d\\n", x);
    return 0;
}
`}
</TryIt>

第二行会打印一个莫名其妙的数字——它编译能过、运行不崩，只是错的。这就是「安静的错」有多难查。

<Pitfall title="把「能跑通」当成「对了」">
  上面这段程序能编译、能运行、有输出。**只有对照期望值才知道它错了。**
  所以做题时一定要拿题目的例子自己验证一遍输出，而不是看到有输出就交。
</Pitfall>

<Pitfall title="调试时只打印一个变量">
  出错时把**相关的值都打印出来**（输入值、中间结果、最终结果），
  再配上标签（`printf("n=%d\n", n)` 而不是 `printf("%d\n", n)`），
  否则你会对着几个裸数字猜哪个是哪个。
</Pitfall>
