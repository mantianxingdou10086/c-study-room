<KeyPoint>
  不同类型混在一个式子里时，C 会先把「精度低」的那个转成「精度高」的，再开始算——
  `int` 遇到 `double`，`int` 先变成 `double`。想改变结果，就用强制转换把某个值提前换掉类型。
</KeyPoint>

## 一条规则：往精度高的那边走

`int` 和 `double` 出现在同一个式子里时，`int` 会被自动转成 `double`，整条式子按 `double` 算。

| 表达式 | 结果类型 | 值 |
|---|---|---|
| `5 / 2` | `int` | `2` |
| `5 / 2.0` | `double` | `2.5` |
| `5.0 / 2` | `double` | `2.5` |
| `(double)5 / 2` | `double` | `2.5` |
| `(int)2.9` | `int` | `2` |

关键点：**转换发生在运算之前**。`5 / 2.0` 不是「先按整数除，再把结果变成浮点」，
而是「先把 5 变成 5.0，再按浮点除」。顺序不一样，结果就不一样。

## 强制转换：把类型名写在括号里

```c
int n = 5;
double a = n / 2;              /* 2.0 —— 先做整数除法得 2，再变成 2.0 */
double b = (double)n / 2;      /* 2.5 —— 先把 n 变成 5.0，再除 */
double c = (double)(n / 2);    /* 2.0 —— 括号里先算完，再转换 */
```

`(double)n` 只作用于**紧跟它的那一个值**。所以括号加在哪一步，结果就可能不一样——
`b` 和 `c` 的区别，是这一节最值得亲手试一次的地方。

## 往精度低的方向转是危险的

- `double` → `int`：小数部分被抹掉，`(int)2.9` 是 `2`，`(int)-2.9` 是 `-2`，还是向零截断
- 大数 → 小类型：超出范围时结果没有保证（第 7 章讲各类型的取值范围）

<TryIt title="五种写法，五个结果">
{`#include <stdio.h>

int main(void)
{
    int n = 5;

    printf("%d\\n", n / 2);
    printf("%.1f\\n", n / 2.0);
    printf("%.1f\\n", (double)n / 2);
    printf("%.1f\\n", (double)(n / 2));
    printf("%d\\n", (int)2.9);
    return 0;
}
`}
</TryIt>

输出依次是 `2`、`2.5`、`2.5`、`2.0`、`2`。
把 `int n = 5;` 改成 `int n = 7;` 再跑一次，看看哪些行变了、哪些行没变。

<Pitfall title="以为 printf 里的 %.1f 会帮你做除法">
  类型转换发生在**算的时候**，不是打印的时候。
  ```c
  int n = 5;
  printf("%.1f\n", n / 2);    /* ❌ 输出 2.0，不是 2.5 */
  ```
  **判据**：先看除号两边有没有浮点数。两边都是整数，就一定做了整数除法，
  后面用 `%.1f` 还是 `%f` 都改不回来。
</Pitfall>

<Pitfall title="强制转换的括号位置写错">
  `(double)n / 2` 是 2.5，`(double)(n / 2)` 是 2.0。
  **判据**：`(类型名)` 只影响它后面紧跟着的那一个值。想让整条式子按浮点算，
  就把转换加在**参与运算的第一个数**前面。
</Pitfall>

<Callout type="tip" title="一个更省事的写法">
  不想写强制转换时，把式子里的某个整数写成小数形式就行：`n / 2.0` 和 `(double)n / 2`
  完全等价，而且更短。两种写法都对，先选一种你能一眼看懂的记住。
</Callout>
