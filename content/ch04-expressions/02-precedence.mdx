<KeyPoint>
  优先级决定「谁先算」，结合性决定「同级的谁先算」。
  拿不准的时候直接加括号——括号不影响程序速度，猜错的代价是半小时调试。
</KeyPoint>

## 优先级：从高到低

| 优先级 | 运算符 | 例子 |
|---|---|---|
| 最高 | `( )` | `(2 + 3) * 4` 先算括号里 |
| 高 | 一元 `-` `+` | `-x + 1` 里的负号先作用于 `x` |
| 中 | `*` `/` `%` | `2 + 3 * 4` 先算 `3 * 4` |
| 低 | 二元 `+` `-` | 最后才算加减 |

实际写代码时不用背表，只用记住一句操作指令：
**先圈出所有的 `*` `/` `%`，它们先算；剩下的 `+` `-` 从左往右算。**

## 结合性：同级从左往右

```c
int a = 100 / 10 / 2;    /* 5，不是 20 */
int b = 20 - 5 - 3;      /* 12，不是 18 */
```

`100 / 10 / 2` 先算左边的 `100 / 10` 得到 10，再除以 2 得到 5。
如果是从右往左，就变成 `100 / (10 / 2)` = `100 / 5` = 20 —— 这是最容易算错的地方。

减法同理：`20 - 5 - 3` 是 `12`，不是 `20 - (5 - 3)` = `18`。

算术运算符**全是左结合**；赋值运算符是少数从右往左结合的（下一节讲）。

## 括号不花钱

```c
int avg = (a + b) / 2;        /* 读者一眼就知道先加后除 */
int sum1 = a + b * c + d;     /* 得先想一下：b * c 先算 */
int sum2 = a + (b * c) + d;   /* 同样的结果，但不用想 */
```

加括号**不会**让程序变慢：编译器本来就知道优先级，括号只是把同一件事写得更清楚。
但它能让下一个读代码的人少做一次推理——包括两周后的你自己。

<TryIt title="一对括号改变结果">
{`#include <stdio.h>

int main(void)
{
    int a = 2, b = 3, c = 4;

    printf("%d\\n", a + b * c);
    printf("%d\\n", (a + b) * c);
    printf("%d\\n", 100 / 10 / 2);
    return 0;
}
`}
</TryIt>

输出是 14、20、5。第二行只多了一对括号，结果就从 14 变成 20。
试着再加一对括号把第三行改成从右往左算，看结果变成多少。

<Pitfall title="把 a + b * c 读成 (a + b) * c">
  **判据**：看到一行里同时出现 `+` 和 `*`，先把 `*` 两边圈起来再算。
  圈不出来（比如式子很长）就加括号——写成 `a + (b * c)`，读的人不用猜。
</Pitfall>

<Pitfall title="把 100 / 10 / 2 算成 20">
  除法是左结合的，先算最左边那一对。
  **判据**：同级的 `/` 连着出现时，从左往右画一遍箭头，不要从右边开始。
</Pitfall>

<Pitfall title="靠背优先级表来写代码">
  表是给**读**代码用的，不是给**写**代码用的。
  写的时候只要你犹豫超过一秒，就加括号——这不是啰嗦，是给别人省时间。
</Pitfall>

<Callout type="tip" title="读别人代码的技巧">
  遇到读不懂的长表达式，用「加括号法」把它重写一遍：按优先级手动补上括号，再对照原来的意思。
  这也是排查「结果和我手算的不一样」时最快的办法。
</Callout>

## 这一节的结论

优先级和结合性合起来只回答一件事：这个式子按什么顺序算。
你能记住最好，记不住也没关系——加括号永远是对的。
