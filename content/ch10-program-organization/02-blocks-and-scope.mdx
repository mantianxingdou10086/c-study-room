<KeyPoint>

  外层变量被遮住了，出了内层又原样回来。

## 块就是一对花括号

一个**块**（block）就是一对花括号包起来的一段代码。你已经见过很多块了，只是没这么叫过：

- 函数的函数体是一个块。
- `if`、`else`、`for`、`while` 后面那对花括号各是一个块。
- 你还可以在函数体里单独写一对花括号，它也是一个块——唯一的作用就是划出一块地盘。

```c
int main(void)
{
    int a = 1;

    {
        int b = 2;      /* b 只在这个内层块里存在 */
        printf("%d\n", a + b);
    }

    /* 到这里 b 已经不存在了 */
    return 0;
}
```

变量的作用域是**从它被声明的那一行开始，到它所在的那个块结束为止**。注意「从声明那一行开始」：同一行之前、同一个块里，这个变量还不存在。

## 名字从哪里找：由内向外

编译器遇到一个名字时，规则只有一条：**从最内层开始往外找，找到第一个同名的就用它，不再继续往外找。**

这条规则带来一个直接后果——**遮蔽**（shadowing）：在内层声明一个和外层同名的变量，那么在内层，这个名字指的就是内层那个。外层的那个变量并没有消失，它只是在这段时间里「看不见」了。

## 遮蔽的三种常见来源

| 来源 | 例子 | 内层生效的是 |
|---|---|---|
| 函数参数和全局变量同名 | 全局 `int value;`，函数写成 `void show(int value)` | 参数 |
| 块里又声明了一次 | 外层 `int n = 10;`，块里 `int n = 20;` | 块里那个 |
| 循环的计数变量 | 外层有 `int i;`，循环写成 `for (int i = 0; ...)` | 循环里那个 |

第一种最危险，因为它会伪装成「我在改全局变量」。第二种和第三种通常是你顺手写的，但结果一样：名字指向了另一个变量。

## 怎么一眼认出遮蔽

给两条能直接用的判据：

1. **同一个名字在一块屏幕上出现了两次，而且两次的缩进深度不同**——那就是遮蔽，内层那次生效。
2. **在函数里改了某个「全局变量」，回到 `main` 却发现它没变**——先去找这个函数里有没有一个同名的局部变量（参数也算）。

预防手段比事后排查省事得多：

- 全局变量的名字起得显眼一点，例如统一带一个前缀，让它不可能和局部变量撞车。
- 局部变量名尽量具体：`total` 到处都是，`sum_of_scores` 只可能有一个。
- 如果干脆不用全局变量，这三种遮蔽里的第一种就永远不会发生。

## 出了块，名字就回来了

遮蔽只在块内生效。块一结束，外层那个变量立刻恢复它原来的含义：

```c
int main(void)
{
    int n = 10;

    {
        int n = 20;
        printf("%d\n", n);   /* 20：内层那个 */
    }

    printf("%d\n", n);       /* 10：外层那个，一直没被改过 */
    return 0;
}
```

这里还有一件事要讲清楚：内层的 `int n = 20;` 不是「给外层的 `n` 赋值」，而是**又造了一个新的变量**。所以内层怎么改，外层都不受影响。想让外层变，就必须写在外层的作用域里，或者用参数和返回值把值传出去。

<Callout type="tip" title="循环里的 i 出了循环就没了">
  写 `for (int i = 0; i < n; i++)`，那个 `i` 只活在循环里。循环结束后再写 `i`，编译器会报错说这个名字没声明。
  要在循环结束后还用到计数变量，就把它声明到循环外面。
</Callout>

<TryIt title="参数遮住全局，块又遮住参数">
{`#include <stdio.h>

int value = 100;

void show(int value)
{
    printf("in show: %d\\n", value);
    {
        int value = 7;
        printf("in block: %d\\n", value);
    }
    printf("back in show: %d\\n", value);
}

int main(void)
{
    show(42);
    printf("in main: %d\\n", value);
    return 0;
}
`}
</TryIt>

四行输出里出现了三个不同的 `value`：`show` 里看到的是参数 42；再往里一层，块的 7 把参数也遮住了；出了块，参数 42 回来；而全局的 100 从头到尾没被碰过，只有在 `main` 里才露了一次面。**全局变量在这段程序里一次都没被修改**——这正是遮蔽最容易骗人的地方。

<Pitfall title="以为在改全局变量，其实改的是同名局部">
  **判据**：函数里改了某个全局变量，回到调用方一看值没变。这时不要怀疑 C 的作用域规则，
  先在函数里找有没有同名声明——最常见的是把参数起成了和全局一样的名字。
</Pitfall>

<Pitfall title="以为内层赋值会传给外层">
  块里写 `int n = 20;` 是造了一个新变量，不是给外层的 `n` 赋值。
  **判据**：块里块外打印同一个名字，结果一个 20 一个 10，而且外层那个从头到尾没变过——
  这就是「两个变量」而不是「一次赋值」。
</Pitfall>

<Pitfall title="循环结束后还想用计数变量">
  `for (int i = 0; ...)` 里的 `i` 属于循环那个块。
  **判据**：编译器报的名字没声明（`undeclared`），而且报错的位置正好在循环后面——把声明挪到循环外面就好。
</Pitfall>

## 这一节的结论

作用域这件事可以压缩成一句话：**花括号划地盘，名字由内向外找，找到就用，找不到才往外。**
遮蔽不是错误，是这条规则的正常结果——但它会让你以为自己改的是另一个变量。
所以记住那条最实用的判据：改了一个变量却看不到效果，先找同名声明。
