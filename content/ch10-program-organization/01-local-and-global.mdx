<KeyPoint>
  局部变量在函数被调用时才出生、函数一返回就消失；全局变量从程序开始一直活到程序结束。
  能用参数和返回值传递的东西，就不要放进全局变量。
</KeyPoint>

## 变量活多久，由定义的位置决定

前面几章里，变量几乎都写在 `main` 里面。从这一节开始，你要养成对每个变量问两个问题的习惯：**谁能看见它**（作用域），**它什么时候出生、什么时候消失**（生命周期）。

- **局部变量**：定义在函数内部（下一节还会看到更小的块）。作用域是它所在的那个块，别的函数看不见它；生命周期是「函数被调用的那段时间」。
- **全局变量**：定义在所有函数外面。作用域是「定义它的那一行往后的所有函数」；生命周期是整个程序的运行期。

| | 局部变量 | 全局变量 |
|---|---|---|
| 定义在哪 | 函数（或块）内部 | 所有函数之外 |
| 谁能看见 | 只有它所在的那个块 | 定义之后的所有函数 |
| 活多久 | 块开始到块结束 | 程序开始到程序结束 |
| 没写初始值 | 内容不确定 | 自动是 0 |

「函数一返回，局部变量就没了」这句话值得具体化一下：同一个函数被调用两次，两次执行里的那个局部变量是**两个不同的变量**。第二次调用不会记得第一次留下的值——想记住，就必须把值放在调用方，靠参数传进去、靠返回值传出来。

## 没写初始值时的差别

全局变量会被自动初始化为 0（`int` 是 0，`double` 是 0.0）。这是 C 标准保证的，不是编译器好心。

局部变量没有这个待遇。它的存储空间是函数被调用时才腾出来的，里面可能还留着上一个函数用过的内容。所以一个没写初始值的局部变量，值是**不确定的**：读它等于读一段来历不明的内存。

<Callout type="warn" title="不要靠运气写代码">
  判据很简单：**你的代码里只要没出现过 `= 0` 这类初值，就不要假设它从 0 开始。**
  全局变量虽然会被自动清零，也建议显式写出来，让读代码的人看见你的意图。
</Callout>

<Callout type="info" title="不确定的值不等于随机数，它是「没规定」">
  它每次运行可能都不一样，也可能碰巧是 0。麻烦的正是「碰巧」：测试时是 0，你以为写对了，
  换个编译器或上线之后它变成别的数——这种 bug 只能靠不写出来避免，不能靠跑一遍发现。
</Callout>

## 全局变量的代价

全局变量确实方便。写一个计数器，如果让 `add` 函数直接改全局变量，函数签名就不用多一个参数，`main` 里也不用接返回值：

```c
int total = 0;          /* 全局 */

void add(int n)
{
    total = total + n;  /* 不经过参数、不经过返回值，直接改外部的变量 */
}
```

但它把「谁改了 `total`」这个问题变难了。代价有三个，都是实打实的：

1. **隐式耦合**。函数之间不通过参数和返回值交换数据，而是通过一个它们都能看见的名字。想知道 `total` 为什么是这个值，你得把整个文件读完。
2. **难测试**。你想单独试一下 `add`，必须先知道它进函数之前依赖哪些全局变量的值——函数不再是一个能独立拿起来用的东西。
3. **容易被遮蔽**。下一节会看到：只要哪个函数里碰巧又声明了一个同名的局部变量，`total = total + n;` 改的就是那个局部变量，全局的那个一动不动。

所以判断标准可以写得很直接：

- 一个变量只被一个函数用到——它**必须**是局部变量。
- 被多个函数用到——先问「能不能用参数传进去、用返回值传出来」。能，就用传参。
- 只有真的没法用传参解决时（例如一份要被很多函数读写的共享表），才用全局变量，并且给它起一个不会跟局部变量撞车的名字。

<TryIt title="一个全局变量活到最后，一个局部变量只能活一次调用">
{`#include <stdio.h>

int total = 0;

void add(int n)
{
    int step = n * 2;

    printf("step  = %d\\n", step);
    total = total + step;
    printf("total = %d\\n", total);
}

int main(void)
{
    add(3);
    add(4);
    printf("total = %d\\n", total);
    return 0;
}
`}
</TryIt>

`add` 被调用了两次，`step` 是两次独立的值（6 和 8），而 `total` 一路累加到 14。把 `total` 改成写在 `add` 里面的局部变量，你再跑一次——它每次都从 0 开始，`main` 最后读到的一定是 0。

<Pitfall title="累加变量忘了清零">
  写 `int sum;` 之后直接 `sum = sum + x;`，加进去的是那段内存里的旧内容。
  **判据**：结果里出现一个离谱的大数，或者第二次运行时结果和第一次不一样——就是这个原因。
  累加变量在使用前必须有一次 `= 0`。全局变量虽然出生就是 0，也别依赖这一点。
</Pitfall>

<Pitfall title="拿全局变量当函数之间的传参通道">
  **判据**：一个变量只被 A 函数写、只在 B 函数读，而 A、B 之间没有任何参数或返回值——这就是隐式耦合。
  改法：把它变成 A 的返回值，再作为参数传给 B。改完之后 B 能单独测试，A 也能。
</Pitfall>

## 这一节的结论

局部变量和全局变量的差别就两条：作用域（谁能看见）和生命周期（活多久）。
「用完就没了」和「整个程序活着」这两种命运，你写 `int x;` 的时候就已经决定了。
能用局部变量就别用全局变量——不是道德要求，而是因为它让「谁改了它」这个问题变得难回答。
下一节我们把作用域放大来看：花括号怎么划出一块地盘，以及内层变量怎么把外层同名变量遮住。
