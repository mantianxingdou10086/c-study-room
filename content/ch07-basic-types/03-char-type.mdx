<KeyPoint>
  `char` 存的不是「字符」，而是字符的编码，也就是一个小整数。`'A'` 就是 65，
  所以 `'a' - 'A'` 能算出 32 这种算术才成立——字符在 C 里可以直接参与运算。
</KeyPoint>

## 一个 char，两种看法

`char` 是整数家族里最小的一员，占 1 个字节。它最特别的地方是：**你可以把它当字符看，也可以把它当数字看**，取决于你用哪个转换说明。

```c
char ch = 'A';

printf("%c\n", ch);   /* A   —— 当字符看 */
printf("%d\n", ch);   /* 65  —— 当数字看 */
```

同一个变量、同一串比特，`%c` 让 printf 把它当编码解释成字符，`%d` 让它当整数解释。这不是类型转换，只是显示方式不同。

## ASCII：字符和数字的对照表

C 里的字符编码用的是 ASCII（以及它的扩展）。你不需要背整张表，记住这三段就够用了：

| 字符 | 编码 | 规律 |
|---|---|---|
| `'0'` 到 `'9'` | 48 到 57 | 连续，且从 48 开始 |
| `'A'` 到 `'Z'` | 65 到 90 | 连续 |
| `'a'` 到 `'z'` | 97 到 122 | 连续 |

三段都是**连续的**，这一点非常有用。因为连续，所以「第几个字母」可以用减法算出来：`'C' - 'A'` 等于 2，说明 `'C'` 是第 3 个字母（从 0 数起）。同理 `'7' - '0'` 等于 7，这就是把一个数字字符变成它代表的数值的标准做法。

## 大小写转换就是加减 32

`'a'` 是 97，`'A'` 是 65，两者相差 32。而且小写和大写的排列顺序完全对应，所以：

```c
char upper = lower - 32;          /* 小写变大写 */
char lower = upper + 32;          /* 大写变小写 */
```

更清楚的写法是拿 `'a'` 和 `'A'` 去算，而不是写死 32：

```c
upper = ch - 'a' + 'A';
```

这两种写法结果一样，但后一种**自己说明了意图**，而且万一将来换了一套字符集，它也不会错。这是「不要写魔数」的一个具体例子。

标准库里有 `toupper()` 和 `tolower()` 专门干这件事，它们在 `ctype.h` 里。本站的运行器不带这个头文件，所以上面这段自己写的版本就是我们的工具。

<TryIt title="字符就是数字：算一算大小写和数字字符">
{`#include <stdio.h>

int main(void)
{
    char lower = 'g';
    char upper;
    char digit = '7';

    upper = lower - 'a' + 'A';

    printf("%c 的大写是 %c\\n", lower, upper);
    printf("'a' - 'A' = %d\\n", 'a' - 'A');
    printf("数字字符 %c 代表的值是 %d\\n", digit, digit - '0');
    return 0;
}
`}
</TryIt>

<Pitfall title="以为 char 一定是无符号的">
  `char` 到底是有符号还是无符号，C 标准**没有规定**，由实现决定。
  在 ASCII 范围（0 到 127）里看不出区别；但只要值超过 127——比如处理 UTF-8 文本的原始字节——
  有符号的 `char` 会变成负数，比较和打印都会出错。
  判据：只要程序要碰「字节」而不是「字母数字」，就用 `unsigned char`，别用 `char`。
</Pitfall>

<Pitfall title="把一个汉字塞进 char">
  一个汉字在 UTF-8 里占 3 个字节，而 `char` 只有 1 个字节。
  写成 `char ch = '中';` 编译器会报错或警告，即使侥幸通过，也只会留下一个残缺的字节。
  判据：需要存多个字符时用字符数组（第 8 章讲数组，第 13 章讲字符串），单个 `char` 只放一个 ASCII 字符。
</Pitfall>
