<KeyPoint>
  二进制浮点只能精确表示「1/2 的幂次组合」这一类数，0.1 这种十进制小数存进去就已经不精确了。
  所以 `0.1 + 0.2 != 0.3` 不是 C 的 bug，而是浮点的本质；比较浮点数要比「差的绝对值」和一个误差范围。
</KeyPoint>

## 两种浮点类型

| 类型 | 字节数 | 有效数字 | 说明 |
|---|---|---|---|
| `float` | 4 | 约 6~7 位 | 单精度 |
| `double` | 8 | 约 15~16 位 | 双精度，日常默认选它 |
| `long double` | 看平台 | 更多 | 精度与实现相关，跨平台差别大 |

写浮点常量时，`3.14` 这种写法默认就是 `double`。要在 `float` 上算，加后缀写成 `3.14f`。日常写程序，**默认用 `double`**——它的精度足够，速度也几乎不差。

## 0.1 存进去的时候就已经不精确了

十进制里 1/3 写不完，只能写成 0.3333...；二进制里 1/10 也一样写不完，它的二进制是 0.0001100110011... 无限循环。`double` 只有 64 位，只能把这个无限小数截断后存起来。

所以变量里那个「0.1」，实际存的近似值是 0.1000000000000000055511151231257827。你看到的 `0.1` 是 printf 帮你四舍五入后的显示，不是内存里的真实值。两个这样的近似值相加，误差就露出来了。

<Callout type="info" title="这不是 C 的毛病">
  只要用 IEEE 754 浮点，结果都一样。在 Python 里输入 `0.1 + 0.2`，你会看到 `0.30000000000000004`；
  在浏览器控制台里输入同样的式子，也是这个数。语言不同，规矩相同——因为大家用的都是同一套二进制浮点表示。
</Callout>

## 想看误差的尾巴，就把位数打满

`%f` 默认只打 6 位小数，误差被藏在了看不见的地方。把精度开到 17 位，尾巴就出来了：

```c
printf("%.17f\n", 0.1);
/* 0.10000000000000001 —— 尾巴出现了 */
```

这解释了一个常见困惑：为什么用 `%f` 打印时一切正常，改成 `==` 比较就出问题。**因为比较用的是内存里的真实值，不是打印出来的那个好看的数字。**

## 比较浮点数要比「误差」

正确的做法不是问「它们相等吗」，而是问「它们的差足够小吗」：

```c
/* ❌ 几乎一定不成立 */
if (a == b) { ... }

/* ✅ 差的绝对值小于误差范围就算相等 */
if (diff < 0 ? -diff : diff) < 1e-9 ...
```

（上面第二行是示意写法，真正的写法是先算出 `a - b` 的绝对值，再和 `1e-9` 比。）

标准库里的 `fabs()` 能算绝对值，但它在 `math.h` 里，本站的运行器不带这个头文件，所以自己写一行三目运算就够：

```c
double d = a - b;
if (d < 0) {
    d = -d;
}
if (d < 1e-9) {
    printf("认为相等\n");
}
```

误差范围取多大，取决于你的数据。算钱用「分」为单位、拿整数存；做物理模拟时 `1e-6` 常常就够。

<TryIt title="0.1 累加十次，它等于 1 吗">
{`#include <stdio.h>

int main(void)
{
    double sum = 0.0;
    double diff;
    int i;

    for (i = 0; i < 10; i++) {
        sum += 0.1;
    }

    printf("sum == 1.0 ? %s\\n", sum == 1.0 ? "相等" : "不相等");

    diff = sum - 1.0;
    if (diff < 0) {
        diff = -diff;
    }
    printf("误差有多大：%.20f\\n", diff);
    printf("打印成 1 位小数：%.1f\\n", sum);
    return 0;
}
`}
</TryIt>

注意最后两行的反差：误差确实存在（不是 0），但按 1 位小数打印时看起来就是 1.0。**误差不会消失，只会被显示格式藏起来。**

<Pitfall title="拿 == 比较浮点数">
  判据：只要看到等号两边有 `float` 或 `double`，立刻停下来想「这两个数是不是算出来的」。
  只要其中一边是运算结果（相加、相乘、相除），就改用误差范围比较。
  如果两个值都是直接从字面量赋进去、中间没做过运算，`==` 是可以的。
</Pitfall>

<Pitfall title="用浮点算钱">
  `0.1 + 0.2` 已经不等于 `0.3` 了，把金额累加几千次，误差会积累到能被用户看见。
  判据：只要涉及金额、计数、序号这类「必须精确」的量，就用整数（以「分」为单位）存，
  只在最后显示时才转成浮点。
</Pitfall>

## 这一节的结论

浮点数是「近似值」，不是「精确值」。三个操作要点：日常用 `double`；不要用 `==` 比较运算结果；
拿不准精度时把小数位打满看一眼。下一节我们回到整数家族里最特别的一位——`char`，
它长得像字符，其实是个小整数。
