<KeyPoint>
  `short`、`int`、`long` 各占几个字节，由平台和编译器决定，C 标准只给了「最低保证」。
  要精确控制宽度，就用 `stdint.h` 里的 `int32_t` 这类定长类型。

## 整数家族有五位成员

C 的整数类型一共五个：`char`、`short`、`int`、`long`、`long long`。每一个都还有一个 `unsigned` 版本（表示「不要负数，把全部位用来表示正数」）。它们能表示的范围不同，占的内存也不同。

| 类型 | 典型字节数（32/64 位桌面） | 典型范围 |
|---|---|---|
| `short` | 2 | -32768 ~ 32767 |
| `int` | 4 | -2147483648 ~ 2147483647 |
| `long` | 4 或 8 | 看平台 |
| `long long` | 8 | 约 ±9.2 乘 10 的 18 次方 |

注意最后两行写的是「看平台」和「约」。这不是偷懒，而是 C 语言真的**没有规定** `int` 一定是 4 字节。

## 标准只给了一个下限

C 标准对整数宽度的要求大意是这样的：`short` 至少 2 字节，`int` 至少 2 字节，`long` 至少 4 字节，`long long` 至少 8 字节；而且顺序不能乱，`sizeof(short)` 不能大于 `sizeof(int)`，`sizeof(int)` 不能大于 `sizeof(long)`。

为什么要写得这么含糊？因为 C 想同时跑在 8 位单片机和 64 位服务器上。对单片机来说，让 `int` 占 4 字节是浪费内存；对服务器来说，让 `int` 只有 2 字节又根本不够用。于是标准把「到底多大」交给每个实现自己去定，只保证一个下限。

<Callout type="info" title="在浏览器里 long 也是 4 字节">
  本站的运行器编译成 32 位 WebAssembly，那里的 `long` 和 `int` 一样是 4 字节。
  你在自己的 64 位电脑上用 gcc 编译同一份代码，`long` 很可能是 8 字节。
  同一份源码、两个不同的答案——这就是「平台相关」的具体样子。
</Callout>

## 想知道多大，就问 sizeof

`sizeof` 运算符给出一个类型或一个变量占多少字节。打印它的写法，本站统一成：

```c
printf("%d\n", (int)sizeof(int));
```

先用 `(int)` 把结果转成 `int`，再用 `%d` 打印。

<TryIt title="看看这台机器上各类型占多少字节">
{`#include <stdio.h>

int main(void)
{
    printf("short        = %d\\n", (int)sizeof(short));
    printf("int          = %d\\n", (int)sizeof(int));
    printf("long         = %d\\n", (int)sizeof(long));
    printf("unsigned int = %d\\n", (int)sizeof(unsigned int));
    return 0;
}
`}
</TryIt>

<Callout type="warn" title="打印 sizeof 用 (int) 包一层">
  `sizeof` 的结果类型是 `size_t`，教科书上的标准写法是配 `%zu`。
  但 `%zu` 在精简的运行环境里不一定被支持，所以本站示例一律写 `(int)sizeof(...)` 配 `%d`。
  字节数最大也就 8，转成 `int` 不会有任何损失。
</Callout>

## 需要精确宽度时，用定长类型

既然宽度是平台相关的，那写「必须精确」的代码时怎么办？用 `stdint.h`：

| 类型 | 含义 |
|---|---|
| `int8_t` / `uint8_t` | 正好 8 位 |
| `int16_t` / `uint16_t` | 正好 16 位 |
| `int32_t` / `uint32_t` | 正好 32 位 |
| `int64_t` / `uint64_t` | 正好 64 位 |

`int32_t` 的意思就是「正好 32 位的有符号整数」。宽度被写进了名字里，不管在哪个平台上编译，它都是 32 位。写网络协议、文件格式、硬件寄存器这类「一个字节都不能差」的代码时，一律用它，不要用 `int`。

<Pitfall title="心里默认 int 够大">
  一旦你发现自己正在心里算「21 亿肯定够用了」，就停下来，把类型写成 `int32_t` 或 `long long`。
  判据很简单：只要这个值来自用户输入、文件或网络，就不能拿「通常够大」当理由——
  下一节的动手课会看到它真的不够大的样子。
</Pitfall>

<Pitfall title="把有符号和无符号混着比">
  `unsigned` 变量和 `int` 变量一起比较时，`int` 会被悄悄转成无符号。于是 `-1 < 1u` 的结果是**假**，
  因为 `-1` 被解释成了 4294967295。判据：比较的两边只要有一边带 `unsigned`，就先问自己
  「另一边会不会是负数」。
</Pitfall>

## 这一节的结论

整数类型的宽度是「约定」，不是「定律」：`int` 通常是 4 字节，但你只能在需要时才依赖它，
需要精确时就用 `stdint.h`。记住三件事：`sizeof` 能问出真实字节数；标准只给下限；
跨平台的代码用定长类型。下一节我们换到浮点数——那里有一个更出名、也更让人困惑的精度问题。
