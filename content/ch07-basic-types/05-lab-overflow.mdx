<KeyPoint>
  溢出不会报错、不会崩溃、不会有警告，它只会悄悄把结果变成另一个数。
  所以选类型前先估算「这个值最大可能是多少」——而不是等程序算错了再回来找。
</KeyPoint>

## 任务

> 写一个程序，让一个 `unsigned int` 从它能表示的最大值再加 1，观察结果；
> 再让一个 `int` 从最大值加 1，观察结果。程序要先把原值打印出来，加 1，再打印一次。

期望输出是四行：

```
4294967295
0
2147483647
-2147483648
```

## 拆解

**第 1 步：无符号的回绕是标准保证的**

`unsigned int` 占 4 字节 = 32 位，全部位都用来表示正数，所以最大值是 2 的 32 次方减 1，也就是 4294967295。再加 1 得到 2 的 32 次方，这已经超出 32 位能表示的范围了。

C 标准明确规定：无符号运算的结果按「模 2 的 32 次方」计算。所以 `4294967295 + 1` 的结果就是 0——**像汽车里程表走满一圈归零一样**。这不是错误，是标准要求的行为。

**第 2 步：有符号的溢出是「未定义行为」**

`int` 的最大值是 2147483647（2 的 31 次方减 1）。加 1 之后，标准没有规定会发生什么——术语叫「未定义行为」。实际上绝大多数编译器会让它按补码回绕，变成 -2147483648。

但你必须知道这个区别：**无符号溢出是标准保证的，有符号溢出不是。** 编译器理论上可以做任何事，包括让这个程序打印别的东西。所以「它会变成负数」这句话，只能当成「我用的这个编译器会这样」，不能当成「C 语言保证这样」。

**第 3 步：写常量别忘了后缀**

`4294967295` 这个字面量超出了 `int` 的范围，所以要写成 `4294967295u`，那个 `u` 告诉编译器「这是一个 `unsigned int` 常量」。

## 完整程序

```c
#include <stdio.h>

int main(void)
{
    unsigned int u = 4294967295u;
    int i = 2147483647;

    printf("%u\n", u);
    u = u + 1;
    printf("%u\n", u);

    printf("%d\n", i);
    i = i + 1;
    printf("%d\n", i);
    return 0;
}
```

注意 `u` 用 `%u` 打印、`i` 用 `%d` 打印——两个变量的类型不同，转换说明也要跟着换。

## 动手：把数值改小，看它多早就溢出

32 位的最大值离生活有点远。把例子换成 `unsigned char`（1 字节，最大值 255），溢出就变得随手可得了：

<TryIt title="让 1 字节的计数器溢出">
{`#include <stdio.h>

int main(void)
{
    unsigned char c = 250;
    int i;

    for (i = 0; i < 10; i++) {
        printf("%d\\n", (int)c);
        c = c + 1;
    }
    return 0;
}
`}
</TryIt>

数一数输出：250 往上走到 255，再下一次就回到 0，然后继续 1、2、3。**没有报错，没有警告，只是数字重新开始数。**

## 怎么选类型：先估算，再选

看完这两个例子，选类型的流程就很清楚了：

1. 问自己「这个值最大可能是多少」，写出一个具体数字。
2. 找一个能装下这个数字的**最小**类型。
3. 拿不准就把这个数字写成注释，放在变量声明旁边。

举一个真实的例子：用 `int` 存**毫秒级时间戳**。2147483647 毫秒等于大约 24.8 天——程序连续运行不到一个月就会翻到负数，然后所有的时间比较全部失效。这个 bug 在测试时几乎不可能出现，上线一个月后才爆发。

<Pitfall title="以为溢出会报错">
  判据：程序没有崩溃、编译器没有警告、但结果荒谬——数字突然变成负数、或者从 255 变成 0——
  那就是溢出。溢出不产生任何信号，你只能靠**看结果**发现它。
  在浏览器里跑上面那段程序时，输出从头到尾都是正常的整数，看不出任何异常。
</Pitfall>

<Pitfall title="拿 int 存时间戳、计数器、金额">
  这三个量都有「随时间无限增长」的性质，而 `int` 是有上限的。
  判据：只要一个变量会被不断累加、或者记录的是「从某个起点到现在」的量，
  就先按最大使用时长算一遍，看会不会撞到上限。撞到了就换 `long long` 或 `unsigned int`。
</Pitfall>

## 这一节的结论

整数类型这一章到这里就结束了：宽度是平台相关的（用 `sizeof` 问、用定长类型锁死）；
浮点是近似值（用误差范围比较）；`char` 是小整数（可以直接做算术）；
强制转换改的是解释方式（截断不是四舍五入）。最后一句话请记住：**溢出不会报错，
所以选类型这件事必须在写代码的时候做，不能留给运行结果去提醒你。**
