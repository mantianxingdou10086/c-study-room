## 两层循环在做什么

把一个矩形打印出来，需要两个维度：几行、每行几个。所以需要两层循环：

```c
int i, j;
for (i = 1; i <= 3; i++) {      /* 外层：第几轮（第几行） */
    for (j = 1; j <= 4; j++) {  /* 内层：这一轮里做什么（第几列） */
        printf("*");
    }
    printf("\n");               /* 换行：一轮结束才做一次 */
}
```

执行过程是：外层第 1 轮 → 内层完整跑 4 次 → 换行；外层第 2 轮 → 内层又完整跑 4 次 → 换行……
**外层每走一步，内层都要从头到尾走一遍**，所以内层循环体一共执行 3 × 4 = 12 次。

看嵌套循环时也有一个省力的办法：把外层变量固定住，只看内层。
「i 等于 2 的那一轮，内层做了 4 次什么」——看懂一轮，剩下的几轮都是它的复制。

## 一个判断谁该放哪的判据

上面那段如果把 `printf("\n");` 挪到内层，输出就变成一竖条 12 行——每个星号一行。

判据是这一句：**「这件事是每轮做一次，还是每个元素做一次？」**
换行是每轮（每行）一次 → 放外层。打印星号是每个元素一次 → 放内层。

## 内层可以看外层

内层的终点可以由外层决定，这是嵌套循环真正有用的地方：

```c
for (i = 1; i <= 4; i++) {
    for (j = 1; j <= i; j++) {   /* 内层跑 i 次 */
        printf("#");
    }
    printf("\n");
}
```

输出 4 行，分别是 1 个、2 个、3 个、4 个 `#`——一个左对齐的三角形。
注意内层的条件用到了外层的 i，所以每轮的次数都不一样。

## 死循环排查三步

程序跑起来就不动了（或一直刷屏），按这个顺序查：

1. **找变量**：把循环条件里的变量圈出来。这个循环的条件里只有谁？
2. **看变化**：从上往下读循环体，这些变量有没有被修改？嵌套循环要**逐层**查——
   外层没问题不代表内层没问题。
3. **单跑内层**：把内层循环拎出来，外层变量换成一个固定值，单独跑一遍，看它能不能停。

<Callout type="tip" title="先让循环只跑一轮">
  调试嵌套循环时，把外层的上界临时改成 1，输出立刻短到能一眼看完。
  看懂一轮再放开，比盯着满屏输出猜快得多。
</Callout>

<TryIt title="内层终点由外层决定">
{`#include <stdio.h>

int main(void)
{
    int i, j;

    for (i = 1; i <= 4; i++) {
        for (j = 1; j <= i; j++) {
            printf("#");
        }
        printf("\\n");
    }
    return 0;
}
`}
</TryIt>

<Pitfall title="内外层用了同一个循环变量">
  ```c
  int i;
  for (i = 1; i <= 3; i++) {
      for (i = 1; i <= 3; i++) {   /* ❌ 内外都是 i */
          printf("*");
      }
      printf("\n");
  }
  ```
  内层把 i 推到 4，外层回头一看条件 `i <= 3` 已经不成立，于是外层只跑了一轮：
  输出是一行三个星号，而不是三行。
  **判据**：外层用 i、内层就用 j，两个循环变量必须是不同的名字。
</Pitfall>

<Pitfall title="把换行写进了内层">
  输出变成一竖条、或者所有内容挤在一行，第一件事就是检查 `printf("\n")` 的缩进：
  它应该和**内层的 for** 对齐，而不是和内层循环体对齐。
  **判据**：换行语句比内层 for 多缩进一层，就说明你放错了地方。
</Pitfall>

## 这一节的结论

外层决定「第几轮」，内层决定「这一轮做什么」，总次数是两层次数的乘积。
循环卡住时，先查循环变量有没有在变——这条经验能解决你以后遇到的大部分卡死。
