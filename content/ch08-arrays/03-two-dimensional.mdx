<KeyPoint>
  二维数组就是「数组的数组」：`m` 是一个数组，它的每个元素本身又是一个数组。
  `m[i]` 是第 i 行——一整行，一个装着若干元素的数组；`m[i][j]` 才是那一行里的第 j 个元素。
  所以中括号要写两次，下标也要给两个。
</KeyPoint>

## 从一张表格说起

一张成绩表有三个学生、四门课。它天然是两个方向的数据：往右是「第几门课」，往下是「第几个学生」。用一维数组存它，就得自己换算「第 i 个学生的第 j 门课排在数组的第几个位置」——很别扭。C 允许数组的元素本身又是数组，于是表格可以直接写出来。

## 定义：两个长度都要写

```c
int m[3][4];
```

第一个数字是**行数**，第二个是**列数**。这一行定义的是一个 3 行 4 列的整数表格，一共 12 个元素，行下标 0 到 2，列下标 0 到 3。

行数和列数都从 0 开始编号，道理和一维数组完全一样：下标表示「离开头几个位置」，所以最后一个行下标是行数减 1，最后一个列下标是列数减 1。

## 数组的数组

把这句话拆开看，就全清楚了：

| 写法 | 它是什么 |
|---|---|
| `m` | 一个有 3 个元素的数组 |
| `m[0]` | 第 1 行——一个长度为 4 的整数数组 |
| `m[1]` | 第 2 行，同样是长度为 4 的数组 |
| `m[1][0]` | 第 2 行第 1 列的那个整数 |
| `m[1][3]` | 第 2 行最后一个整数 |

`m` 的元素类型不是 `int`，而是「长度为 4 的整数数组」。所以 `m[0]` 拿出来的是**一整行**，想再往里拿一个具体的数，就还要再来一次中括号：`m[1][0]`。

## 内存里它其实是一排

虽然写起来是两个方向，但内存是一条线。二维数组的存放规则叫**行优先**：第 1 行的 4 个元素排完，接着排第 2 行的 4 个元素，再排第 3 行。

```c
m[0][0] m[0][1] m[0][2] m[0][3] m[1][0] m[1][1] ... m[2][3]
```

这就是为什么「数组的数组」这个说法是准确的：它真的是「三行」一个接一个拼起来的。记住这个画面，以后写循环时就知道行和列哪个该在外层。

## 初始化：嵌套的花括号

按行写，每一行用一对花括号包起来：

```c
int m[2][3] = {
    {1, 2, 3},
    {4, 5, 6},
};
```

也可以把内层花括号省掉，按顺序一个一个填：

```c
int m[2][3] = {1, 2, 3, 4, 5, 6};
```

两种写法结果一样：先填满第 1 行的 3 个位置，再填第 2 行。**写了初始化列表，没写到的元素一样会补 0**——这条规则在二维数组里同样成立。

## 遍历要用两层循环

一维数组要一个循环，二维数组就要两个：外层走行，内层走列。

```c
for (i = 0; i < 3; i++) {
    for (j = 0; j < 4; j++) {
        printf("%d ", m[i][j]);
    }
    printf("\n");
}
```

执行顺序是：`i` 等于 0 时，`j` 从 0 走到 3，把第 1 行打完；然后 `i` 变成 1，再打第 2 行……外层每转一圈，内层转满一整圈。这正好对应「一行一行往下读」的自然顺序。

判据很简单：**最外层的循环变量，只出现在第一个中括号里**。上面这段里 `i` 只写在 `m[i][j]` 的前一个位置，所以它走的是行。

<TryIt title="打印一个 3 行 4 列的表格，并算出每行的和">
{`#include <stdio.h>

int main(void)
{
    int m[3][4] = {
        {5, 8, 2, 4},
        {1, 9, 3, 7},
        {6, 6, 0, 2},
    };
    int i, j, rowsum;

    for (i = 0; i < 3; i++) {
        rowsum = 0;
        for (j = 0; j < 4; j++) {
            rowsum = rowsum + m[i][j];
        }
        printf("row %d sum = %d\\n", i, rowsum);
    }
    return 0;
}
`}
</TryIt>

三行的和分别是 19、20、14。注意 `rowsum = 0;` 写在**外层循环里、内层循环外**：每换一行都要重新开始累加。如果写到外层循环外面，第二行的和会从第一行的结果继续加。

## 换个顺序就是按列走

把两层循环调换位置，就变成按列处理：

```c
for (j = 0; j < 4; j++) {
    sum = 0;
    for (i = 0; i < 3; i++) {
        sum = sum + m[i][j];
    }
    printf("col %d sum = %d\n", j, sum);
}
```

同一张表，这样打出来的四列和是 12、23、5、13——因为每一列是把三个不同行、同一个列下标的元素加起来。判据还是那一条：现在最外层的 `j` 只出现在第二个中括号里，所以它走的是列。

<Pitfall title="两个下标之间写逗号">
  `m[1, 2]` 不是「第 2 行第 3 列」。中括号里只有一个表达式，逗号在这里是逗号运算符，
  整个式子等价于 `m[2]`——一个数组，而不是你要的那个元素。
  **判据**：中括号里的两个下标之间出现逗号，一定是错的。元素必须写成 `m[1][2]`，
  两对中括号，两次下标。
</Pitfall>

<Pitfall title="内外层循环的变量用反了">
  外层写 `j`、内层写 `i`，程序仍然能跑完，但遍历顺序变成了「一列一列」，
  和后面那句 `printf("\n")` 想表达的「每行一行输出」对不上。
  **判据**：看最外层循环的变量出现在第几个中括号里。想按行遍历，外层变量必须写在第一个中括号里。
</Pitfall>

<Pitfall title="定义时漏写第二个长度">
  `int m[3][];` 编译不过：编译器要按「一行有多少个元素」来算出每个元素的位置，
  列数缺了就算不出来。
  **判据**：定义一个二维数组时，两个长度都要写；只有以后学函数形参时，
  才会看到省略第一维的写法。
</Pitfall>

## 这一节的结论

二维数组没有新概念，它只是「元素又是数组的数组」。三句话带走：定义时写 `m[行][列]`；`m[i]` 是整行、`m[i][j]` 才是元素；遍历用两层循环，外层变量管行、内层变量管列，累加变量要放在内层循环外、外层循环里。
