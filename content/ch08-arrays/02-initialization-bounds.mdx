<KeyPoint>
  C 不检查下标越界：在长度为 10 的数组上访问 `a[10]`，程序不会报错、不会提醒你，
  它只是去读写一块不属于这个数组的内存——可能什么也不发生，也可能让程序崩掉，
  或者悄悄改掉别的变量。所以边界这件事，只能由你自己保证。
</KeyPoint>

## 声明之后数组里是什么

先记住一条规则：**`int a[5];` 这样的定义不会把元素清零**。这 5 个位置里装的是内存里原来剩下的东西，是不确定的值。读它、拿它参与运算，得到的结果没有任何意义。

只有写了初始化列表，元素才会被填上确定的值：

```c
int a[5] = {1, 2, 3, 4, 5};
```

## 初始化的几种写法

| 写法 | 结果 |
|---|---|
| `int a[5] = {1, 2, 3, 4, 5};` | 5 个元素按顺序全部填满 |
| `int a[5] = {1, 2};` | 前两个是 1 和 2，**后面三个自动补 0** |
| `int a[5] = {0};` | 全部是 0——最常用的「清零」写法 |
| `int a[] = {1, 2, 3};` | 长度由列表决定，这里是 3 |
| `int a[5] = {[4] = 9};` | 指定下标初始化：只有 `a[4]` 是 9，其余补 0 |

第二行和第三行是同一条规则的两个用法：**只要写了初始化列表，没写到的元素就补 0**。所以「部分初始化」和「没初始化」是两件完全不同的事——前者剩下的位置是 0，后者是不确定的值。

## 长度可以问 sizeof

如果不想把长度写两遍，可以让数组自己报出来：整个数组的字节数除以单个元素的字节数，就是元素个数。

<TryIt title="部分初始化、清零，以及用 sizeof 数出长度">
{`#include <stdio.h>

int main(void)
{
    int a[10] = {3, 1, 4};   /* 只写了前三个 */
    int b[10] = {0};         /* 全部为零 */
    int n = (int)(sizeof(a) / sizeof(a[0]));

    printf("n = %d\\n", n);
    printf("a[0]=%d a[1]=%d a[2]=%d a[3]=%d\\n", a[0], a[1], a[2], a[3]);
    printf("b[0]=%d b[9]=%d\\n", b[0], b[9]);
    return 0;
}
`}
</TryIt>

`n` 打印出来是 10，说明长度算对了；`a[3]` 是 0（没写到的位置补 0），`b[9]` 也是 0。

<Pitfall title="sizeof 数长度忘了除以元素大小">
  写成 `sizeof(a)`，得到的是**字节数**：如果是 10 个 `int`，结果是 40。
  **判据**：算出来的长度如果明显偏大（比如声明的是 10，算出来 40），就是漏了
  `sizeof(a[0])` 这个除数。正确写法是 `sizeof(a) / sizeof(a[0])`。
</Pitfall>

## 越界：C 不会拦住你

现在讲本章最大的坑。假设 `a` 的长度是 10，合法下标是 0 到 9。那么写 `a[10]` 会怎样？

答案是：**什么都不会发生——不会报错，不会警告，编译也照样通过**。C 语言对中括号里的数字不做任何范围检查。编译器只把它翻译成「从数组开头数 10 个位置，去那里取一个整数」，它不问那里到底有没有东西。

于是 `a[10]` 会去访问紧挨着数组后面的那块内存。后果有三种可能，全都真实存在：

| 情况 | 你会看到什么 |
|---|---|
| 那块内存没有别的东西在用 | 程序照常跑完，读到一个莫名其妙的值 |
| 那块内存里正好是别的变量 | 读到别人的值；如果是**写入**，就改坏了那个变量 |
| 那块内存根本不属于这个程序 | 程序立刻崩掉（运行器里表现为退出码非 0） |

最坏的地方在于它的**不确定性**：同一句越界代码，今天跑出来是 12345，明天换个输入就崩了。你不能靠「我刚才试过没事」来证明代码是对的。

## 边界怎么算才对

写循环之前先做一道减法题，就能把越界彻底挡在门外：

| 数组长度 | 合法下标 | 遍历的循环条件 |
|---|---|---|
| 5 | 0 ~ 4 | `i < 5` |
| 10 | 0 ~ 9 | `i < 10` |
| N | 0 ~ N-1 | `i < N` |

把循环条件写成 `i < 长度` 是标准写法，也可以写成 `i <= 长度 - 1`，两者等价——但更容易写错，因为一不小心就会漏掉那个 `- 1`。

<TryIt title="三种循环条件的对照：正确的是哪一个">
{`#include <stdio.h>

#define N 5

int main(void)
{
    int a[N] = {2, 4, 6, 8, 10};
    int i, sum;

    sum = 0;
    for (i = 0; i < N; i++) {
        sum = sum + a[i];
    }
    printf("i < N    : %d\\n", sum);

    sum = 0;
    for (i = 0; i <= N - 1; i++) {
        sum = sum + a[i];
    }
    printf("i <= N-1 : %d\\n", sum);

    sum = 0;
    for (i = 0; i < N - 1; i++) {
        sum = sum + a[i];
    }
    printf("i < N-1  : %d\\n", sum);
    return 0;
}
`}
</TryIt>

前两种都得到 30（5 个数全部加到了），最后一种得到 20——`i < N - 1` 少走了最后一轮，把 `a[4]` 也就是 10 漏掉了。**漏掉一个元素不会报错，它只是让结果变小**，所以这类错误往往要到结果对不上时才发现。

再想一下把条件写成 `i <= N`（注意是小于等于、且没有减 1）：`i` 会取到 5，也就是 `a[5]`——长度 5 的数组下标最大只有 4，这一次访问就是越界。

<Pitfall title="以为初始化了一部分，剩下的是垃圾值">
  `int a[5] = {1, 2};` 之后 `a[4]` 是 0，不是垃圾值。
  **判据**：看声明那一行有没有 `= {...}`。有，没写到的位置就补 0；没有（比如 `int a[5];`），里面才是不能读的不确定值。
</Pitfall>

<Pitfall title="以为越界会报错">
  程序没有崩溃、编译器没有报警、结果却不对——很多人第一反应是「逻辑写错了」，其实下标早就走出去了。
  **判据**：先数一遍循环里的下标。把循环最后一次的值写出来，看它是否小于长度；
  再看每一个直接写死的下标（比如 `a[10]`），和数组长度对一下。
</Pitfall>

<Pitfall title="给数组整体赋值">
  `int a[3] = {1, 2, 3};` 是对的，但
  ```c
  int b[3];
  b = a;          /* 编译不过 */
  ```
  是错的：数组不能整体赋值，只能一个一个元素搬。
  **判据**：`=` 右边是 `{...}` 的写法，**只能出现在声明那一行**；声明之后再用 `=`，左边就必须带下标。
</Pitfall>

## 这一节的结论

两条规则请一起记住：**写了初始化列表，没写到的元素补 0；C 从不检查下标越界。**

前者让你能安心地只写前几个值，后者意味着边界的正确性完全由你负责——循环条件写 `i < 长度`，直接写死的下标先和长度对一遍。下一节把数组从一条线扩展成一个表格：两个下标的数组。
