<KeyPoint>
  数组让一批同类型的数据共用一个名字，用下标区分彼此。
  下标从 0 开始，所以长度为 N 的数组，合法下标是 0 到 N-1。
  它天生和循环配对：一个从 0 数到 N-1 的循环，刚好把每个元素走一遍。
</KeyPoint>

## 为什么需要数组

假设要处理一个班 8 个学生的成绩。用前面学过的办法，你会写 8 个变量：`s1`、`s2`、`s3`……一直写到 `s8`。名字越写越长，而且学生人数一变成 50，整段代码就得重写。

再仔细看这 8 个变量，它们的共同点非常明显：**类型相同**（都是 `int`）、**地位相同**（都是成绩）、**只差一个编号**。C 为这种情况准备了专门的写法——一个名字，加一个编号。这就是数组。

## 定义数组要写三件事

```c
int a[5];
```

这一行里有三个信息：类型 `int`（每个元素都是整数）、名字 `a`、长度 `5`（一共放 5 个元素）。中括号里的数字是**元素个数**，不是最大下标——这两个数字差 1，是本课最容易出错的地方。

数组的每个元素都用一个名字加中括号来写，中括号里的东西叫**下标**：

| 想访问 | 写法 |
|---|---|
| 第 1 个元素 | `a[0]` |
| 第 2 个元素 | `a[1]` |
| 第 5 个（最后一个） | `a[4]` |
| 不存在的第 6 个 | `a[5]` |

## 下标从 0 开始

为什么第一个元素是 `a[0]` 而不是 `a[1]`？因为下标表达的是「**离开头有多远**」，不是「第几个」。`a[0]` 的意思是「离开头 0 个位置」，也就是开头那个；`a[4]` 是「离开头 4 个位置」，也就是第 5 个。长度为 5 的数组，最后一个元素离开头正好 4 个位置。

于是有一条可以随身带的判据：**最后一个合法下标 = 长度 - 1**。长度为 10 的数组，合法下标是 0 到 9；写成 `a[10]` 就已经走出去了（下一节专门讲走出去会怎样）。

「第几个」和「下标」的换算也一样：第 k 个元素的下标是 k-1。所以想访问第 3 个元素，写的是 `a[2]`。

## 用循环走一遍每个元素

有了下标，访问数组就有了一个从 0 数到 N-1 的动作——这正是 `for` 循环的形状：

```c
for (i = 0; i < 5; i++) {
    printf("%d\n", a[i]);
}
```

这三行里有三个必须照抄的细节：

1. **从 0 开始**：`i = 0`，因为第一个下标就是 0。
2. **条件是小于**：`i < 5`，不能写 `i <= 5`。写成小于等于，`i` 会一路走到 5，那一次访问就是越界。
3. **下标变量要提前声明**：`int i;` 写在 `main` 的开头，和别的变量放在一起。

这段循环的执行过程是：`i` 等于 0 时打印 `a[0]`，等于 1 时打印 `a[1]`……等于 4 时打印 `a[4]`，然后 `i` 变成 5，条件不成立，循环结束。每个元素正好被访问一次。

## 数组和循环是天生一对

一旦能把每个元素走一遍，「对每个元素做同一件事」就都变成了往循环体里加一行代码。求和就是最典型的例子：先在循环外面把累加变量清零，再在循环里把每个元素加进去。

<Callout type="tip" title="累加的三步固定套路">
  第一步：循环之前写 `sum = 0;`。第二步：循环里写 `sum = sum + a[i];`。
  第三步：循环之后再用 `sum`。顺序错了（比如在循环里清零）结果一定是错的。
</Callout>

<Callout type="info" title="数组的长度是「一次定义、到处使用」">
  下面这段代码把长度写成了一个常量 `N`。好处是：以后数组要放 10 个数，
  只需要把 `#define N 5` 改成 `#define N 10`，定义和循环会一起变，
  不会出现「数组改了、循环忘了改」这种错误。
</Callout>

<TryIt title="遍历数组、打印每个元素，并求和">
{`#include <stdio.h>

#define N 5

int main(void)
{
    int a[N] = {7, 3, 9, 1, 6};
    int i, sum;

    sum = 0;
    for (i = 0; i < N; i++) {
        printf("a[%d] = %d\\n", i, a[i]);
        sum = sum + a[i];
    }
    printf("sum = %d\\n", sum);
    return 0;
}
`}
</TryIt>

输出里每一行都是 `a[下标] = 值`，最后一行是 5 个数的和 26。把 `N` 改成 3 再跑一次，数组里只留下 `{7, 3, 9}`，输出会跟着变成 3 行——定义和循环用的是同一个常量，所以永远同步。

<Pitfall title="把「第几个」直接当下标写">
  要访问第 3 个元素却写成 `a[3]`，拿到的是第 4 个。
  **判据**：写下标前先问一句「离开头几个位置」。第 1 个是 `a[0]`，第 k 个是 `a[k-1]`，
  最后一个永远是 `a[长度-1]`。
</Pitfall>

<Pitfall title="循环条件写成小于等于">
  `for (i = 0; i <= N; i++)` 会让循环多走一次，那一次的下标正好等于数组长度。
  **判据**：看循环的最后一次，把那个下标值算出来。只要它等于长度，就是越界。
  遍历整个数组的标准写法只有一种：`i = 0; i < N`。
</Pitfall>

## 这一节的结论

数组的三个要点：一个名字装一批同类型数据；下标从 0 开始、最后一个合法下标是长度减 1；遍历用 `for (i = 0; i < N; i++)`，长度写成常量让定义和循环保持同步。

把「遍历」和「累加、比较」拼起来，就能解决一批以前很啰嗦的问题——这正是本章动手课要做的事。但在那之前，得先搞清楚两件更危险的事：数组没写满的时候里面是什么，以及下标走出去了会怎样。
