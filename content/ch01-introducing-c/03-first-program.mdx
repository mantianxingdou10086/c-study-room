<KeyPoint>
  一个 C 程序的最小骨架就是：一个叫 `main` 的函数 + 一对花括号。
  其他所有东西——`#include`、`printf`、`return 0`——都是围绕这个骨架的服务设施。
</KeyPoint>

## 逐字拆开

```c
#include <stdio.h>

int main(void)
{
    printf("hello\n");
    return 0;
}
```

| 这一行 | 在说什么 |
|---|---|
| `#include <stdio.h>` | 「把标准输入输出的声明拿进来」——因为下面要用 `printf` |
| `int main(void)` | 定义一个叫 `main` 的函数，它**返回一个整数**，**不接受参数** |
| `{` | 函数体开始。花括号圈起来的部分才是函数真正做的事 |
| `printf("hello\n");` | 调用 printf，让它打印 `hello` 和一个换行 |
| `return 0;` | 函数结束，返回 0 给调用者 |
| `}` | 函数体结束 |

## 为什么必须是 main

一个程序可能有几百个函数，但**操作系统只会从 `main` 开始执行**。它不是普通函数：

- 名字固定，不能改成 `Main` 或 `start`
- 一个程序（准确说是整个可执行文件）里只能有一个 `main`
- 它的返回值会变成**退出状态码**：0 表示「一切正常」，非 0 表示「出事了」

`int main(void)` 里的两个关键词各有含义：

- 前面的 `int`：返回一个整数（就是那个退出状态码）
- 括号里的 `void`：明确表示「这个函数不接收任何参数」

<Callout type="info" title="写成 main() 行不行？">
  在 C 里 `int main()` 也能编译通过，它的意思是「参数不确定」。
  但**本站统一写 `int main(void)`**，因为它是 C 的规范写法，意思明确，也避免了「不确定」带来的隐患。
  顺带说：JSCPP 那种 C++ 解释器不认 `(void)` 这个写法，这也是本站默认用真编译器的原因之一。
</Callout>

## 分号、花括号、缩进：三个必须养成的习惯

**1. 每条语句结尾要有分号。** 不是「一行一个分号」，而是「一个语句一个分号」——`return 0;` 后面要，`printf(...)` 后面要，但 `#include` 和函数定义那一行后面**不要**。

**2. 花括号要配对。** 每个 `{` 都要有一个 `}`。养成「先写一对空花括号，再往里面填内容」的习惯，能省掉大量「缺右花括号」的排查时间。

**3. 缩进不是给编译器看的。** 编译器不在乎你缩不缩进，但**你在乎**：缩进错了，你会在错误的地方找 bug。

## 转义字符：怎么打印一个换行

`printf` 的字符串里，`\` 开头的组合叫转义字符：

| 写法 | 打印出来的东西 |
|---|---|
| `\n` | 换行 |
| `\t` | 制表符（对齐用） |
| `\\` | 一个反斜杠本身 |
| `\"` | 一个双引号 |
| `%%` | 一个百分号 |

最后两个特别容易踩：字符串是用双引号包起来的，所以字符串里想出现双引号，必须写成 `\"`；`%` 在 printf 里有特殊含义（后面接转换说明），想打印字面的 `%` 要写 `%%`。

<TryIt title="自己改一改：让输出变成两行" stdin="">
{`#include <stdio.h>

int main(void)
{
    printf("第一行");
    printf("第二行");
    return 0;
}
`}
</TryIt>

试试在两句话中间加一个 `\n`，看看输出有什么变化。这个「printf 不自动换行」的性质，是新手最常见的意外之一。

<Pitfall title="忘了分号，编译器却指着下一行报错">
  编译器发现「这条语句还没结束就换行了」，于是把报错位置定在**它期望分号的地方**——
  有时就是你漏掉的那一行的下一行开头。所以报错行号只信一半：**先看它指的那一行和上一行**。
</Pitfall>

<Pitfall title="return 0 之后写代码">
  `return` 一执行，函数立刻结束。写在它后面的语句永远不会被执行（有些编译器会警告 unreachable code）。
  这不是「注释掉就不报错」的问题——是逻辑写错了位置。
</Pitfall>
