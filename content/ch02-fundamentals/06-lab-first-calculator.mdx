<KeyPoint>
  把公式变成程序，真正难的不是写算式，而是**确定每一步的数据类型**。
  两个整数相除，结果还是整数——这一步会让很多「看起来对」的公式算错。
</KeyPoint>

## 一个真实的任务

> 输入一个摄氏温度，输出对应的华氏温度，保留 1 位小数。
> 公式：华氏 = 摄氏 × 9 ÷ 5 + 32

先别写代码，按这四步走：

**第 1 步：需要哪些数据？**
一个摄氏温度（输入，整数）、一个华氏温度（输出，要小数）。

**第 2 步：各用什么类型？**

| 数据 | 类型 | 理由 |
|---|---|---|
| 摄氏温度 | `int` | 用户输入整数 |
| 华氏温度 | `double` | 结果可能是 98.6 这种小数 |

**第 3 步：运算里有没有整数除法？**
`c * 9 / 5` —— `c` 是 int，`9` 是 int，所以 `c * 9` 是 int；再除以 int 的 `5`，
结果**还是 int**，小数部分被直接丢掉。这就是陷阱。

**第 4 步：修掉它。**
把其中一个数写成小数形式，整个运算就会变成浮点运算：

```c
f = c * 9.0 / 5 + 32;    /* 9.0 是 double，于是整条式子按浮点算 */
```

<Callout type="warn" title="整数除法的规则只有一句">
  **两个整数相除，结果是整数**（向零截断，不是四舍五入）。
  `1 / 2` 是 `0`，`333 / 5` 是 `66`，`7 / 2` 是 `3`。
  想得到小数，参与运算的数里**至少要有一个是浮点**。
</Callout>

## 完整程序

```c
#include <stdio.h>

int main(void)
{
    int c;
    double f;

    scanf("%d", &c);
    f = c * 9.0 / 5 + 32;
    printf("%.1f\n", f);
    return 0;
}
```

输入 `37`，输出 `98.6`。

## 自己动手：故意用整数算一次

下面这段是「错」的版本——但它能编译、能运行、会输出一个数：

<TryIt title="错误示范：全用整数算" stdin="37">
{`#include <stdio.h>

int main(void)
{
    int c = 37;

    printf("%d\\n", c * 9 / 5 + 32);
    return 0;
}
`}
</TryIt>

它输出 `98`，而不是 `98.6`。把 `37` 改成 `100` 再试一次——这次两个版本都会得到 `212`，
因为 100 × 9 ÷ 5 恰好能整除。

<Callout type="tip" title="这类 bug 为什么最难查">
  它不报错、不崩溃，只在**某些输入下**算错。
  上面这个例子里，输入 100 是对的、输入 37 是错的——所以你测的时候很容易「碰巧没发现问题」。
  **多试几个输入**，尤其是不能被整除的那种。
</Callout>

<Pitfall title="scanf 忘了 &">
  ```c
  scanf("%d", c);    /* ❌ 少了 &，程序可能直接崩 */
  ```
  这是初学者第一大错误。记住：**scanf 的每个变量前面都要有 `&`**。
</Pitfall>

<Pitfall title="输出格式和题目要求不一致">
  题目要求「保留 1 位小数」，就得用 `%.1f`。用 `%f` 会输出 `98.600000`，
  用 `%d` 会输出垃圾。**输出格式也是题目的一部分**。
</Pitfall>
