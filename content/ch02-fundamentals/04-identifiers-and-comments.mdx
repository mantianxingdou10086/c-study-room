<KeyPoint>
  标识符就是你自己起的名字（变量、函数、类型）。规则很窄：字母、数字、下划线，
  **不能以数字开头**，不能和关键字撞名。规则之外，好名字的标准只有一条：**别人一眼能看懂它装的是什么**。
</KeyPoint>

## 硬规则

一个合法的标识符必须满足：

1. 只能由**字母、数字、下划线** `_` 组成（区分大小写：`Age` 和 `age` 是两个不同的名字）
2. **不能以数字开头**：`2ndPlace` ❌、`place2` ✅
3. 不能是**关键字**（`int`、`return`、`if`、`while` 等语言保留字）
4. 不能包含空格、减号等符号：`second-place` ❌

对照着看：

| 名字 | 合法？ | 原因 |
|---|---|---|
| `count` | ✅ | |
| `_temp` | ✅ | 下划线开头是允许的 |
| `student_age` | ✅ | 下划线分隔，清晰 |
| `x2` | ✅ | 数字不在开头就行 |
| `2x` | ❌ | 数字开头 |
| `student age` | ❌ | 有空格 |
| `student-age` | ❌ | 减号不是合法字符（还会被当成减法） |
| `int` | ❌ | 关键字 |

## 关键字

关键字是语言自己占用的词，你不能拿来当变量名。现在只需要眼熟这些：

```
int   double   char   return   if   else   while   for   do
switch   case   break   continue   void   const   struct
```

写多了自然会记住——IDE 通常会把它们显示成另一种颜色。

<Callout type="tip" title="命名风格：C 的社区习惯">
  常见两种：`student_age`（下划线，C 传统风格）和 `studentAge`（驼峰，跨语言风格）。
  **本站统一用下划线风格**，因为 C 标准库就是这种风格（`strlen`、`printf`）。
  最重要不是选哪种，而是**整个项目保持一致**。
</Callout>

## 好名字 vs 坏名字

```c
int a;              /* ❌ 一周后你自己也不知道 a 是什么 */
int n;              /* 🤔 数学公式里可以，其他地方尽量别用 */
int cnt;            /* ❌ 省了 3 个字母，代价是每次都要想一下 */
int studentCount;   /* ✅ */
int student_count;  /* ✅ 本站风格 */
```

另一个真实场景——**布尔意义的变量不要用否定式**：

```c
int notReady = 1;      /* ❌ 判断时要想两层：if (notReady == 0) ... */
int isReady = 0;       /* ✅ */
```

## 注释：写「为什么」，不写「做了什么」

```c
/* ❌ 复述代码：读者自己看得懂 */
i = i + 1;   /* 把 i 加 1 */

/* ✅ 解释原因：这是代码本身说不出来的信息 */
i = i + 1;   /* 跳过表头行，从第一行数据开始读 */
```

<Pitfall title="注释和代码不一致">
  改代码时忘了改注释，是比没注释更坏的情况——它会让下一个读代码的人（包括三个月后的你）
  相信一个错误的事实。**改了代码就顺手改注释**，改不动就删掉它。
</Pitfall>

<Pitfall title="用注释屏蔽代码而不是删掉">
  ```c
  /* printf("调试信息\n"); */
  ```
  临时调试可以，但别留在提交里。看不懂的注释掉的代码只会让文件越来越难读。
</Pitfall>

## 这一节的结论

标识符的硬规则很少（字母数字下划线、不以数字开头、避开关键字），
真正的功夫在命名：让名字替你解释代码，让注释只解释「为什么」。
