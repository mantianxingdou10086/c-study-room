<KeyPoint>
  `return` 一执行，函数立刻结束，并把值交给调用方。
  声明了返回类型的函数，每条执行路径都必须走到 `return`——忘了写，调用方拿到的是垃圾数据。
</KeyPoint>

## return 同时干了两件事

很多人对 `return` 的印象只是「返回一个值」，其实它同时做了两件事：

1. **结束**当前函数：`return` 后面的语句一律不再执行。
2. **交回**一个值给调用方（`main` 的 `return 0;` 交回的是给操作系统的退出码）。

所以 `return` 不只是「给结果」，它还是函数体里的一个出口。第 6 章循环里的 `break` 是「跳出循环」，`return` 就是「跳出整个函数」。

## void 表示「不交回值」

`print_sep` 那种只干活、不产出数据的函数，返回类型写 `void`：

```c
void print_sep(void)
{
    printf("================\n");
}
```

`void` 函数里也可以写 `return;`，但那只是「提前结束」，后面不跟任何值：

```c
void warn(int n)
{
    if (n == 0) {
        printf("nothing to do\n");
        return;          /* 提前收工，后面不打了 */
    }
    printf("n = %d\n", n);
}
```

反过来，声明成 `void` 却写 `return 0;` 是错的——函数既然不交回值，就不该给它一个值。

## 提前 return：把特殊情况挡在门口

一个函数里真正的主流程通常很短，长出来的部分大多是「特殊情况」。惯用写法是：进门先处理特殊情况，处理完直接 `return`，剩下的代码就是主流程。

<TryIt title="提前 return 让主流程留在函数末尾">
{`#include <stdio.h>

int check(int n)
{
    if (n < 0) {
        return -1;
    }
    printf("checking %d\\n", n);
    return n * 2;
}

int main(void)
{
    printf("%d\\n", check(5));
    printf("%d\\n", check(-3));
    return 0;
}
`}
</TryIt>

看输出：传 `5` 时先打了 `checking 5` 再交回 `10`；传 `-3` 时**一句 `checking` 都没打**，直接交回 `-1`——那次 `return` 一执行，函数就结束了。

## 忘了写 return 会怎样

一个声明为 `int` 的函数，如果有一条执行路径没走到 `return`，会怎么样？答案是：**调用方拿到垃圾数据。**

C 标准对这种情况不作保证（属于未定义行为）。实际运行时，函数的返回值通常放在一个固定的地方，而那个地方留着上一次运算的残留内容——于是你得到一个荒唐的数字，而且它可能每次运行都不一样。

## 返回类型不会「救」回丢掉的小数

返回值会被**隐式转换**成函数的返回类型——但转换发生在**算完之后**，它救不回整数除法已经丢掉的小数：

```c
double half(int n)
{
    return n / 2.0;      /* int / double → 按浮点算，交回的是 0.5 这种值 */
}

double percent(int a, int b)
{
    return a * 100 / b;  /* ⚠️ 整条式子全是 int，先算成整数除法，小数已经没了 */
}
```

**判据**：返回类型是 `double` **不代表**式子里会按浮点算。看的是 `return` 后面那个表达式里有没有浮点数——和第 4 章那条规则一模一样，只是在函数里更容易忘。

## 一个函数只能交回一个值

想同时拿到「结果」和「算得成不成功」两样东西时，暂时（还没学指针）只能用一个约定的特殊返回值表示失败：

```c
int divide(int a, int b)
{
    if (b == 0) {
        return -1;       /* 用 -1 表示「这个我算不了」 */
    }
    return a / b;
}
```

**判据**：约定一旦定下，**每个调用方都必须检查**它。写成 `printf("%d\n", divide(a, b))` 直接打印，等于没做错误处理——这正是「函数只能返回一个值」带来的真实代价，后面学了指针和结构体才会有更干净的写法。

## main 的 return 0 不是形式主义

`main` 的返回值是**给操作系统的退出码**：`0` 表示正常结束，非 0 表示出了问题。别的程序（脚本、构建工具、CI）就是靠它判断这次运行成没成功——所以 `main` 结尾那句 `return 0;` 是有作用的，不是在凑格式。

<Pitfall title="只在部分分支里写了 return">
  写法上看起来「都覆盖到了」，实际漏了一条路径。比如先判断 `n > 0` 返回结果，却忘了 `n` 等于 0 时该返回什么。
  **判据**：把函数体当流程图走一遍，从入口出发列出**每一条能走到末尾的路径**，每条都必须经过 `return`。数不出路径数，就说明这个函数的分支太多，该拆了。
</Pitfall>

<Pitfall title="以为「没写 return 就是返回 0」">
  有些语言的函数没有返回值会默认给 0 或 null，C 不这么干。C 不会替你补一个默认值。
  **判据**：调用方打印出来的结果是一个你没见过的大数（比如 32767、或者类似 -1073741764 这样的数），而函数里看上去算得没错——先去检查那条没写 `return` 的路径。
</Pitfall>

<Pitfall title="在 return 后面接着写代码">
  ```c
  return n * 2;
  printf("done\n");   /* 永远执行不到 */
  ```
  **判据**：如果一个 `printf` 从来没出现在输出里，而它就在 `return` 后面几行，那它不是没生效——它根本不会被执行。编译器有时会警告「unreachable code」，别忽略这类警告。
</Pitfall>

## 这一节的结论

`return` 的两个作用要一起记：交回值、结束函数。带返回值的函数，每条路径都要走到 `return`；`void` 函数则用不跟值的 `return;` 提前收工。判断「函数写没写对」最省事的办法，就是把它的每条出口都列出来看一眼。
