## 局部变量能用到哪一行

到目前为止，你写的变量几乎都是「局部变量」：在函数体（或者一对花括号）里声明，只在这个范围里有效。

规则很短：**从声明它的那一行开始，到它所属的那对花括号结束为止。**

```c
int main(void)
{
    int i;

    for (i = 0; i < 3; i++) {
        int t = i * 2;      /* t 在这里出生 */

        printf("%d\n", t);
    }

    printf("%d\n", t);      /* 错：t 已经死了 */
    return 0;
}
```

`t` 是在 `for` 的花括号里声明的，出了那对花括号就不存在了。形参也是局部变量——它的「花括号」就是整个函数体，所以函数一结束，形参也就没了。

<Callout type="info" title="同名变量会遮住外层的那一个">
  内层花括号里声明的变量，如果和外层同名，内层这一个会在它的范围里「遮住」外层的。
  这种写法能编译通过，但读起来很容易看错，第 10 章会专门讲它为什么是 bug 高发区。
  现在先记住一条判据：**看到一个变量在两个地方同名，先确认你现在看的是哪一层。**
</Callout>

## 函数可以调用自己

既然函数能被 `main` 调用，那它也能被自己调用。这种写法叫**递归**。

最经典的例子是阶乘：`5!` 等于 `5 × 4 × 3 × 2 × 1`。注意它自己就带着一层同样的结构：`5!` 等于 `5 × 4!`。把这句话翻译成代码：

```c
int fact(int n)
{
    if (n <= 1) {
        return 1;              /* 终止条件：不用再问了，直接给答案 */
    }
    return n * fact(n - 1);    /* 剩下的问题：n 乘上 (n-1) 的阶乘 */
}
```

两行就写完了，而且比循环版本更接近数学定义本身。

## 递归必须有能停下来的地方

`fact` 里第一行的 `if (n <= 1) return 1;` 叫**终止条件**（也叫基准情形）。它的作用是：**在这一层不要再调用自己了，直接给一个确定的值。**

没有它，`fact(5)` 会去调 `fact(4)`，`fact(4)` 去调 `fact(3)`……永远没有尽头。每调用一层，内存里都要为这一层留出一块地方（放参数、局部变量和返回地址），这些地方一个叠一个，堆在一块叫**栈**的区域里。函数一层层压进去、永远不弹出，栈就被耗尽——程序直接崩溃，这叫**栈溢出**。

<TryIt title="阶乘和斐波那契：两个能停下来的递归">
{`#include <stdio.h>

int fact(int n)
{
    if (n <= 1) {
        return 1;
    }
    return n * fact(n - 1);
}

int fib(int n)
{
    if (n < 2) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main(void)
{
    int i;

    printf("5! = %d\\n", fact(5));
    for (i = 0; i < 8; i++) {
        printf("%d ", fib(i));
    }
    printf("\\n");
    return 0;
}
`}
</TryIt>

`fib` 的终止条件写在最前面：`n` 小于 2 时直接返回 `n` 本身（`fib(0)` 是 0、`fib(1)` 是 1）。剩下的情况再拆成两个更小的问题——`fib(n-1)` 和 `fib(n-2)`。两个函数都满足递归的两条要求：**有一个不用再调用自己的情况，而且每次调用自己时参数都在变小。**

## 递归是怎么一层层走回来的

以 `fact(3)` 为例，看它到底发生了什么：

1. `fact(3)` 里 `n` 是 3，不满足终止条件，于是要算 `3 * fact(2)`——先暂停，等 `fact(2)` 的结果。
2. `fact(2)` 同样暂停，等 `fact(1)`。
3. `fact(1)` 命中终止条件，直接交回 1，不再往下调。
4. `fact(2)` 拿到 1，算出 `2 * 1 = 2` 交回；`fact(3)` 拿到 2，算出 `3 * 2 = 6` 交回。

注意第 3 步之前，三层调用都还「挂在半空中」：它们的形参和局部变量都还占着内存，等着下层交回结果。这也是递归比循环慢、而且不能太深的原因。反过来，只要终止条件可靠，每一层都能等到自己的答案。

## 递归和循环怎么选

阶乘、斐波那契用循环也能写，递归不是非用不可。经验判断：

- 问题本身是「一层套一层」的（比如后面要学的树结构、目录遍历），递归写起来最自然。
- 只是「重复做 n 次」的，用循环更直接，也更快——`fib(30)` 这样的递归会重复计算很多遍，慢得离谱。
- 递归深度不能太深：每多一层就多占一块栈空间，几万层就可能溢出。所以练习用阶乘、斐波那契这种浅递归就够了。

<Pitfall title="忘了写终止条件">
  函数里只有「调用自己」这一条路，递归永远停不下来，程序会直接把栈用光。
  **判据**：程序启动后几秒内直接退出、一行输出都没有，或者报出和栈有关的错误——先去看递归函数的终止条件还在不在。
</Pitfall>

<Pitfall title="终止条件写了，但参数没有向它靠近">
  比如把调用写成 `return n * fact(n);`——终止条件是 `n <= 1`，可参数 `n` 一直是原来那个数，条件永远不成立，一样会栈溢出。
  **判据**：看每一次递归调用传下去的参数，它必须**比上一次更接近**终止条件。`fact(n - 1)` 满足，`fact(n)` 不满足。
</Pitfall>

<Pitfall title="以为递归里外层的变量是一份">
  每一层递归调用都有一套自己的形参和局部变量，它们互不干扰。
  **判据**：看到递归函数里 `n` 的值每层都不一样，这是正常的——不是「变量被改坏了」。想让某一层的值留到下一层，就得当成参数传下去，或者用返回值交回来。
</Pitfall>

## 这一节的结论

作用域告诉你「一个变量从哪行活到哪行」，递归则是「函数调用自己 + 一个能停下来的条件」这两件事合起来。递归写不对，八成是这两件里少了一件——要么没有终止条件，要么参数没有朝终止条件走。
