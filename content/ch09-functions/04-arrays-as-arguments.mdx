<KeyPoint>
  数组传参传的是首元素的地址，不是整个数组的副本，所以函数里改元素就是改原件。
  也正因为传的不是整个数组，函数拿不到长度——长度必须另开一个参数传进来。
</KeyPoint>

## 形参写成数组的样子

上一章你已经会遍历数组了。如果「给数组每个元素加 1」这件事要在程序里做三次，就该把它写成函数。数组形参的写法是在类型后面加一对中括号：

```c
void add_all(int a[], int n, int k)
{
    int i;

    for (i = 0; i < n; i++) {
        a[i] = a[i] + k;
    }
}
```

调用的时候，括号里写数组名，长度和别的参数照常跟在后面：

```c
int a[4] = {1, 2, 3, 4};

add_all(a, 4, 10);
```

注意 `a` 后面**没有**中括号——调用时只写名字。中括号只出现在定义和声明里。

## 长度为什么要单独传

这是初学者最容易卡住的地方：为什么不能像 `main` 里那样，用 `sizeof(a) / sizeof(a[0])` 在函数里算出长度？

因为在函数里，形参 `a` 已经不是「一个数组」了，它只是一个**首元素的地址**。对一个地址做 `sizeof`，得到的是地址本身的大小（本站运行器上是 4 字节），和数组有多长毫无关系。`sizeof(a) / sizeof(a[0])` 会算出 1 这种荒唐的结果。

所以规矩是：**数组长度必须自己算好，作为另一个参数传进去。** 惯例是把长度紧跟在数组后面，形参就叫 `n`，让读代码的人一眼看出「这两个参数是一组的」。

<Callout type="info" title="函数只认「首元素地址」和「长度」这两样">
  函数体里能拿到的信息只有两样：从哪里开始（`a`）、有多少个（`n`）。
  它不知道数组原来的名字，也不知道数组在调用方那边占了多大——所以 `n` 写错，函数就会越界读写，而 C 不会拦你。
</Callout>

## 函数里改，外面也变

这是数组参数和普通参数最大的区别。看一眼：

<TryIt title="函数把整个数组清零，调用方看得见">
{`#include <stdio.h>

void fill_zeros(int a[], int n)
{
    int i;

    for (i = 0; i < n; i++) {
        a[i] = 0;
    }
}

int main(void)
{
    int a[5] = {3, 1, 4, 1, 5};
    int i;

    fill_zeros(a, 5);
    for (i = 0; i < 5; i++) {
        printf("%d ", a[i]);
    }
    printf("\\n");
    return 0;
}
`}
</TryIt>

`fill_zeros` 里一个 `return` 都没有，`main` 里的数组却被改成了全 0。原因不神秘：`a[i]` 和 `main` 里的 `a[i]` 指的是**同一块内存**。函数收到的不是数组的副本，而是「数组从哪儿开始」这个信息。

## 值传递的规则变了吗

没有变。值传递这条规则依然成立：函数拿到的永远是一份副本。只是这次复制过去的东西恰好是**地址**——复制地址不影响「改原件」，因为两个地址指向同一块内存。

这也解释了另一件事：函数里**可以**修改数组元素，但**不能**让调用方的数组变成另一个数组。你传进去的地址是副本，改地址本身调用方看不到。

<Pitfall title="忘了传长度，在函数里写死长度">
  比如 `for (i = 0; i < 5; i++)`，写死了 5。这样的函数只能服务长度为 5 的数组，换个数组就错。
  **判据**：函数体里出现一个长度数字（5、10、100），问自己一句「换个长度的数组它还能用吗？」不能，就把它换成形参 `n`。
</Pitfall>

<Pitfall title="在函数里用 sizeof 求数组长度">
  函数体里写 `int n = sizeof(a) / sizeof(a[0]);` 一定错：`a` 在函数里是首元素地址，`sizeof(a)` 是 4，整个式子的结果是 1。
  **判据**：只要 `sizeof(a) / sizeof(a[0])` 出现在**函数体**里，结果就是错的。它只在「数组本身还活着」的地方（比如 `main` 里刚声明完的那个数组）才算得对。
</Pitfall>

<Pitfall title="函数改了数组，调用方却以为没改">
  与上一条相反的坑：以为数组也遵循「改形参不影响调用方」，于是在函数里改完数组，又在外面重新算一遍。
  **判据**：数组参数改元素之后，调用方**不需要**做任何事——直接读原数组就是新值。反过来，如果函数只是**把整个数组换成另一个**（比如 `a = b;`），那调用方不会有任何变化。
</Pitfall>

## 这一节的结论

数组作为参数，记住三句话：形参写 `int a[]` 的样子，长度用另一个参数 `n` 传进去，函数里改元素就是改原件。第 8 章那些「求和、求最值、求平均」的循环，现在都可以搬进函数里，`main` 也就跟着变短了。
