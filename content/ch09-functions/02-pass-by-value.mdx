<KeyPoint>
  C 永远传副本：调用函数时，实参的值被复制一份交给形参。
  函数里改的是这份副本，调用方的变量一点没动——想改原件，只能把地址传进去。
</KeyPoint>

## 一次调用里到底发生了什么

写 `area(3, 4)` 的时候，C 做的事情分成四步：

1. 先算出实参的值：`3` 和 `4`。
2. 给形参 `w`、`h` 各自分配一小块新空间，把 3、4 **复制**进去。
3. 执行函数体——函数里读写的都是这两块新空间。
4. 函数结束，这两块空间连同函数一起消失。

关键在于第 2 步的「复制」。形参 `w` 和实参 `3` 是两个彼此独立的东西，只是值相同。这条规则叫**值传递**（也叫传值调用），它是 C 语言里唯一的一种参数传递方式。

<Callout type="info" title="形参其实就是「已经赋好初值的局部变量」">
  函数一开始执行，形参被创建；函数一结束，形参就消失。
  调用方那边根本不知道它们存在过——所以函数里怎么折腾形参，外面都感觉不到。
</Callout>

## 亲手看一眼「改了没反应」

「交换两个变量的值」是检验值传递最经典的例子。把交换写成一个函数：

<TryIt title="函数里的交换，为什么外面没变">
{`#include <stdio.h>

void swap(int a, int b)
{
    int t = a;

    a = b;
    b = t;
    printf("in swap: a = %d, b = %d\\n", a, b);
}

int main(void)
{
    int x = 1;
    int y = 2;

    swap(x, y);
    printf("in main: x = %d, y = %d\\n", x, y);
    return 0;
}
`}
</TryIt>

`swap` 里面确实换成功了，打印出 `a = 2, b = 1`；可是回到 `main` 再打印，`x` 和 `y` 还是 `1` 和 `2`。函数里那次交换动的是副本，副本在函数结束时就被丢掉了。

## 想改原件，只能传地址

那「交换两个变量」这种需求到底怎么实现？答案是：不要传变量本身，要传它的**地址**。函数拿到地址之后，就能顺着地址找到原变量并修改它。

地址怎么表示、怎么用，是第 11 章（指针）的主题。这里先记住结论：**C 没有「自动帮你改原件」的机制，想改原件就必须自己把地址传进去。** 所以你在后面看到的每一个「函数把结果写回调用方」的例子，背后都是地址在起作用。

<Callout type="warn" title="别靠「函数会改我的变量」来写代码">
  如果一段逻辑依赖「调用某个函数之后，我传进去的变量会变」，那么在 C 里几乎一定是错的。
  判据：函数调用之后发现变量的值和调用前一模一样，而函数里明明改过它——这就是值传递，不是 bug。
</Callout>

## 那数组呢

第 4 节会看到，数组作为参数时函数改得动原件。这不是推翻了值传递——数组传参时，复制过去的是「首元素的地址」，地址指向的还是同一块内存。规则没变，只是这次复制的东西恰好是一个地址。

<Pitfall title="以为「传进去了」就等于「传的是原件」">
  「把变量传进函数」这句话本身没有说清任何事：传进去的永远是一份副本。
  判据：改完以后回到调用方看那个变量——变了，说明传的是地址；没变，说明传的是值。想不清楚就先按「没变」去预期，再看实际结果。
</Pitfall>

<Pitfall title="用全局变量绕开传参">
  看到「函数里要改外部的数据」，有人会把那个变量改成全局变量，让函数直接访问。这样能跑，但函数的输入输出变成了隐式的：只看函数定义看不出它依赖谁、会改谁。
  判据：一个函数体里出现了既不是形参、也不是它自己声明的变量名，就说明耦合已经发生了。全局变量的代价第 10 章会讲清楚。
</Pitfall>

## 这一节的结论

值传递是这一章最需要记牢的一条：**函数拿到的是副本。** 记住它，你就不会写出「指望函数帮我改一个 `int`」的代码，也不会在调试时对着「函数里明明改了」发愣。
