# 题库与判题：设计决定与踩坑

> 147 道题（第 1 章 12、第 2 章 15、第 3~10 章各 15），四种题型：
> MCQ 56 / FILL 32 / OUTPUT 30 / CODE 29。
> 其中 **59 道（29 CODE + 30 OUTPUT）的期望答案由真编译器逐题验证**（`tests/integration`）。
> 判分器复用讲义里的随堂检测（`src/lib/judge/validators.ts`），所以不会出现"课上判对、题库判错"。

---

## 1. 设计决定

| 决定 | 理由 |
|---|---|
| **答案绝不下发到浏览器**，判题在服务端 | 题目内容存在仓库里（可 git diff），但仓库是服务端的。只要不把 `validator.correct` / `expectedStdoutAny` / `referenceAnswer` 塞进 props，它们就不会进客户端 bundle。有专门用例抓页面 HTML 验证这一点 |
| 代码题走「**浏览器跑出 stdout → 服务端比对标准答案**」 | 矛盾点：代码必须在浏览器里跑（clang 是 WASM），但标准输出不能下发。解法是只把运行结果传上去，比对仍在服务端 |
| 参考答案**按需从服务端取**（`revealReferenceAnswer`） | 当 prop 传就等于下发到浏览器；而且"看过答案"这件事必须记在服务端，否则刷新页面就洗白了 |
| XP **只在首次通过时发**（`Submission.xpAwarded` 累加） | 一个用户对一道题只有一条记录（`@@unique([userId, exerciseId])`），幂等天然成立 |
| **提示不影响 XP**，只有看答案才不计 | 鼓励学生先看提示自己想办法；把提示也惩罚掉会让人直接去看答案 |
| 题库页**静态** + 客户端进度叠加；练习页**动态** | 沿用 M4 的做法保住静态生成（构建实测 29 个静态页）；练习页本来一人一份状态，动态更简单 |
| 代码题的 stdout 由客户端上报（理论上可伪造） | 这是他自己网站上的自学进度，作弊只坑自己。不值得为此上服务端沙箱编译（成本极高） |

## 2. 测试抓到的真 bug：规则形同虚设

**现象**：展开参考答案后，答对仍然拿到 XP。

**根因**：判 XP 时用的是**客户端传上来的** `input.viewedAnswer`：

```ts
// ❌ 错：客户端没有理由主动承认自己看过答案
const xpGained = verdict.passed && !alreadyPaid && !input.viewedAnswer ? xp : 0;
```

**修法**：以服务端自己的记录为准（客户端的值只用来"提前告知"，不作为依据）：

```ts
// ✅ 对：服务端的记录优先
const viewedAnswer = (existing?.viewedAnswer ?? false) || (input.viewedAnswer ?? false);
const xpGained = verdict.passed && !alreadyPaid && !viewedAnswer ? xp : 0;
```

**教训**：凡是"惩罚/限制"类规则，判定依据必须在服务端。前端传来的状态只能用于优化体验，不能用于裁决。

## 3. 两个测试工程上的坑

### 3.1 断言必须写 `exact: true`，否则时过时不过

`getByText("共 42 题")` 同时命中顶部徽章和未登录提示里的括号文字 → strict mode 报错。
单独跑时因为进度快照还没加载完（未登录提示尚未渲染）只命中一个，所以**偶发通过** —— 这种"看心情的测试"比直接失败更糟。

### 3.2 不要并发跑 vitest 和 playwright

两者都要读同一份 Wasmer 工具链（`public/toolchain/clang.pkg.gz`）。
同时跑会让集成测试（真 clang 验证题目答案）失败并跳过一批用例，看起来像代码坏了。
**实测**：并发时 `57 passed | 19 skipped`，单独跑 `75 passed | 1 skipped`（全绿）。

## 4. 验收

```bash
npx playwright test tests/e2e/exercises.spec.ts --workers=1   # 6 个用例
```

| 用例 | 验的是什么 |
|---|---|
| 题库页：列出全部题目并按章分组 | 42 题按章分组，能点进去 |
| 未登录：题库页/练习页都提示登录 | 不会出现"点了没反应" |
| **答案不下发到浏览器** | 抓练习页 HTML，确认不含参考答案正文 |
| 选择题：选错给人话诊断，再选对通过 | 诊断是 `选的是第 1 个，再想想：把每个选项代进条件里推一遍…`（只给方向），通过后 `+5 XP · 等级 1 · 连续 1 天` |
| **代码题：真编译真运行** | 用参考解提交 → 首次初始化 clang → 通过并拿 XP（约 6 秒） |
| 展开参考答案后不再给 XP | `看过参考答案，这道题不再计 XP`，且文案里没有 `+5 XP` |

全量：**32 passed**（登录 6 + 课程 9 + 进度 5 + 题库 6 + 练习场 6）。
