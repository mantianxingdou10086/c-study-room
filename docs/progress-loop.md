# 学习进度闭环（M4）：设计决定与踩坑

> 「登录后进度存档」是这个站点区别于普通教程站的根本，也是最初需求里的第一条。
> 这份文档记录它怎么实现的，以及这轮踩到的坑。

---

## 1. 设计决定

| 决定 | 理由 |
|---|---|
| 进度快照走 **`/api/progress` + 客户端 Provider**，不在页面里 `await auth()` | 在页面里读会话会让课程地图和 15 个讲义页变成**动态渲染**，丢掉静态生成。放客户端异步取，页面继续 SSG（实测：构建后仍是 29 个静态页） |
| 整个页面**只发一次**请求 | 课程地图有 10 个章节卡片，每章各发一次就是 10 个请求。用一个 Context 统一取，所有小标记从它读 |
| XP **只在第一次完成时发放**（靠 `LessonProgress.xpAwarded` 判断） | 不能靠 `completedAt` 判断：那样"取消完成 → 再标记完成"可以反复刷 XP。所以 schema 里专门加了这个字段（迁移 `0002_lesson_xp_awarded`） |
| 取消完成时**不追回** XP | 学生确实学过了，追回只会让人恼火；靠 `xpAwarded` 保证不会再发第二次 |
| 连续打卡按 **UTC+8 自然日** 算，且同一天多次学习**幂等** | 不能用服务器本地时区：Vercel 跑在 UTC，中国用户晚上 8 点后的学习会被算到"第二天"，打卡会莫名断掉 |
| 徽章**定义写在代码里**，数据库只记「谁在什么时候拿到哪个」 | 加/改徽章不需要迁移，也不会出现"库里存着一条已经没有定义的徽章" |

### 激励规则（都在 `src/lib/gamify/xp.ts`，纯函数 + 15 条单测）

- 一节课：讲义 10 XP、动手课 20 XP
- 升级曲线：`25 × (n-1) × n` → 2 级 50、3 级 150、4 级 300、5 级 500（新手期反馈快，后面拉长）
- 连续打卡：昨天学过 +1，断一天重置为 1，同一天重复不算
- 7 枚徽章：第一个程序、开张、第 1 章通关、连学三天/一周、500 XP、十连对

## 2. 两个「写了但忘了接上」的缺口（都是测试逼出来的）

### 2.1 `recordLessonVisit` 没挂到页面上 → 「继续上次学习」永远不会出现

`recordLessonVisit` 这个 server action 写好了，但**没有任何地方调用它**。
结果：「继续上次学习」只在有「未完成」课时时才显示，而由于从不记录足迹，
用户永远不会留下未完成记录 → 按钮永远不出现。

**修法**：加 `<RecordLessonVisit>` 客户端组件挂在讲义页上，登录后进页面时报一次足迹
（服务端幂等：已有记录就不再写库，所以每次进页面调用没有负担）。

### 2.2 `ChapterProgressLine` 写了但没放进课程地图 → 只有环形进度没有数字

环形进度条能看出"大概学了点"，但看不出"3/4 还是 3/5"。组件写好了，忘了加进章节卡片。

**教训**：这两个都是"代码存在、单测不会发现、只有端到端跑一遍才会暴露"的缺口。
e2e 断言写的是**用户能看到什么**，所以它能抓到这类问题。

## 3. 测试设计上的一个大坑（值得单独记）

**现象**：某个用例失败后，后面好几个用例报"用户不存在"，和真实原因完全无关。

**根因**：Playwright 在**任何用例失败后会重启 worker**，而文件级 `afterAll`
（我用来清理测试账号的钩子）会**在重启前提前执行** —— 于是共享的那个测试账号被删掉，
后面依赖它的用例全部失败。

**证据**：正常跑时清理日志出现 1 次；一旦有失败，清理日志出现多次（中间那次就是重启触发的）。

**修法**：**每个用例自己注册账号，不要共用**。改动后每个用例都能独立运行、独立失败，
报错也直指真实原因。

另外两条同类的改进：

1. **等跳转失败时把页面上的错误抓出来报**，而不是只给一个 30 秒超时。
   加上这个之后立刻抓到了真实原因：用户名 21 字符超过 20 字符上限（**测试数据不合规，
   应用的校验是对的**）。
2. 用 `data-testid` 定位错误提示，不要 `getByRole("alert")`（Next 自带的
   `__next-route-announcer__` 也带这个 role）。

## 4. 验收

```bash
npx playwright test tests/e2e/progress.spec.ts --workers=1   # 5 个用例
```

| 用例 | 验的是什么 |
|---|---|
| 标记完成：拿到 XP，按钮状态翻转，进度写进服务器 | `+10 XP · 等级 1 · 连续 1 天 · 新徽章「开张」`；进度页显示 `1 / 15` |
| XP 幂等：取消完成再标记，不会重复加分 | 提示"这一节的 XP 之前已经发过了"，XP 仍是 10 不是 20 |
| **换一个浏览器上下文登录，进度仍然在** | **全新 cookie 罐登录后进度仍是 1** —— 排除 localStorage 假象；并验证「继续上次学习」指向未完成的第 2 节 |
| 未登录时不显示标记按钮，而是引导登录 | 不会出现"点了没反应" |
| 未登录时课程地图不显示进度标记 | 页面保持静态渲染，未登录也正常显示内容 |

实测输出：

```
提示文案 → +10 XP · 等级 1 · 连续 1 天 · 新徽章「开张」
提示文案 → 已记录（这一节的 XP 之前已经发过了）
26 passed（全量 e2e：登录 6 + 课程 9 + 进度 5 + 练习场 6）
```
